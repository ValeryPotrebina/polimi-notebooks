A

Back to the letters
ACID atomicity, consistency, isolation, durability

The four properties a relational DBMS guarantees for every transaction (pp. 189–192): it happens entirely or not at all, it leads from a consistent state to a consistent state, it does not show its intermediate states to others, and its committed effects last. ACID is why relational systems remain the choice where reliability and consistency are essential (p. 204).

Lessons 3 5 See also: atomicity, consistency (ACID), isolation, durability, BASE

action

An operation that "triggers execution" and returns a value to the driver or writes data out (p. 1211): count(), collect(), take(n), first(), reduce(f), saveAsTextFile(path), and on DataFrames show(). collect() copies the whole dataset into the driver's memory; take(n) only n elements.

Lessons 38 39 See also: transformation, stage

agent (Flume)

The "Simplest unit in Flume" (p. 944): one process that moves events through three components (p. 948). A source accepts incoming data and writes it to a channel; a channel stores it in the order received — a memory channel is fast but not persistent, a file channel survives a restart; a sink removes it from the channel and sends it downstream. An event is a header of metadata, usable for routing, and a body of bytes; a source's channel selector replicates every event to every channel or multiplexes them by header.

Lesson 33 See also: Flume, at-least-once delivery

aggregate-based

The NoSQL stores whose unit is an aggregate — a cluster of related data read, written and moved together, like a hospital with its buildings and departments: "Key-value and document-based" (p. 168). The other group of p. 168 is relationship-based, the graph databases, whose unit is the connection between nodes. Fowler and Sadalage (NoSQL Distilled) count column-family stores such as Cassandra as aggregate-oriented too; the slide names only key-value and document.

Lesson 4 See also: document, key-value store, graph database

aggregation (Elasticsearch) aggs

Counting and computing over the matching documents without returning the documents themselves: "size": 0, "aggs": { "per_score": { "terms": { "field": "SCORE" } } } returns one bucket per value with its doc_count, ten buckets by default. Metric aggregations compute numbers (count, min, max, avg, sum), bucket aggregations group documents (terms, range, filters), pipeline aggregations take other aggregations as input; an aggregation inside a bucket aggregation is a sub-aggregation, computed per bucket.

Lesson 26 See also: keyword (field type), $group

aggregation pipeline

db.collection.aggregate([ {stage}, {stage}, … ]): an array of stages applied in order, each a document with one key, the stage's name, each receiving the documents the previous one produced. The practical lectures teach six stages — $match, $group, $unwind, $sort, $limit, $project — and the paper of 30 January 2026 asks to "use only the pipeline stages discussed during the practical lectures" and to design "without using the MongoDB $lookup operation", the stage that joins collections.

Lessons 14 15 See also: $match, $group, $unwind, projection

ALLOW FILTERING

The clause that lets CQL run a query that breaks the WHERE rules — every partition-key column with = or IN, clustering columns as a prefix with one final range, no OR, any other column only with an index: Cassandra then reads rows and discards those that fail, so the cost grows with the table, not with the answer. A last resort; cheap only inside one partition.

Lesson 21 See also: secondary index, partition key, clustering key

analyzer

The program that turns a text into the terms of the inverted index (p. 589). The standard analyzer cuts on word boundaries, removes most punctuation and lowercases, and removes stop words only if configured; simple, whitespace, stop, keyword (no-op), pattern and language analyzers do otherwise — a language analyzer also stems. POST /_analyze shows the tokens.

Lesson 25 See also: text (field type), inverted index, match query, bag of words

anomaly

What redundancy costs: an update anomaly (one fact sits in several rows, so changing it means changing every copy), an insertion anomaly (a fact cannot be stored without an unrelated one) and a deletion anomaly (deleting one fact deletes another).

Lesson 9 See also: normalization, denormalization

API Application Programming Interface; web API

"A set of rules and protocols that allows different software applications to communicate with each other and exchange data. Often can be called remotely" (p. 1510). A web API is called over HTTP: a method and a URL, and the answer is data, usually JSON. GET reads — "As an end-user, the most used requests for APIs are GET requests" (p. 1511) — POST creates, PUT updates, DELETE removes.

Lesson 34 See also: URL, JSON, web scraping

Application Master AM

In YARN, the per-application process for "job scheduling and monitoring": it "negotiates resource containers from the Scheduler, tracking their status and monitoring for progress", and "itself runs as a normal container". A container is a share of one machine's CPU and memory in which one process of an application runs — a map task, a Spark executor, the Application Master.

Lesson 31 See also: YARN

approximate nearest neighbour (ANN) ANN

A search that returns vectors that are very probably the nearest, much faster than the exact search, at the price of sometimes missing one. Its quality is measured by recall: recall@k is the share of the true k nearest neighbours that the approximate search returns. LSH, HNSW and IVFPQ are approximate.

Lessons 27 28 See also: LSH, HNSW, IVF, product quantization (PQ)

at-least-once delivery

A delivery guarantee: no event is lost, but after a failure one may be delivered twice. Logstash gives it with its persistent queue, Flume with transactional hand-offs between durable channels, Storm by replaying tuples. It is not exactly-once.

Lessons 25 33 See also: Logstash, Flume, Storm

atomic operation atomic command

An operation that runs as one indivisible step: no other client's command can run between its read and its write, so "ATOMIC OPERATIONS are not affected by problems in case of concurrent access" (p. 1587). Two clients that each GET 10 and SET 11 lose an increment — a lost update; two INCRs give 12.

Lessons 17 18 See also: Redis, transaction

atomicity

All or nothing (p. 189): a transaction that commits takes effect completely; one that rolls back or fails before the commit is undone (UNDO); one whose commit happened before a fault is redone (REDO). The slides name the mechanisms "abort-rollback-restart" and commit protocols.

Lesson 3 See also: ACID, transaction

attribute

A property of an entity or of a relationship, with a domain, the set of values it may take — the papers note it in brackets: Allergies (Yes/No). A composite attribute is made of sub-attributes. In the relational model an attribute is a named column of a relation.

Lessons 6 7 8 See also: entity, derived attribute

availability

"Node failures do not prevent other survivors from continuing to operate (a guarantee that every request receives a response about whether it succeeded or failed)" (p. 195): a real answer, not an error or a timeout.

Lesson 5 See also: CAP theorem

Avro

A "language neutral data serialization system" (p. 1243): row-oriented and binary, with its schema written in JSON in the file's header, so records carry no field names. Sync markers between blocks make a file splittable, and it supports schema evolution — producers and consumers at different versions of the schema.

Lesson 40 See also: Parquet

bag of words

A document represented only by how many times each term occurs in it: the text is "scanned and parsed" and "Word occurrences are counted (may be stemmed)" (p. 556). The order of the words is thrown away.

Lesson 24 See also: TF-IDF, lexical gap

BASE Basically Available, Soft state, Eventually consistent

The NoSQL alternative to ACID (p. 203): the system answers even during failures, its state may change while replicas converge, and the replicas agree eventually. Developers must be "more knowledgeable and rigorous about consistent data" (p. 204); "BASE properties may be enough" (p. 215).

Lesson 5 See also: ACID, eventual consistency, soft state

BeautifulSoup Beautiful Soup; bs4

A Python parser for HTML (and XML) that extracts data from a page that is already fully loaded (p. 1533). For a static page it is enough together with a downloader such as curl or requests.

Lesson 34 See also: web scraping, Scrapy, Selenium

big data

Data that the classical approach, one machine and one schema designed in advance, cannot handle. The slides characterise it by four V's, each with a two-word gloss — Volume "data at scale", Variety "data in many forms", Velocity "data in motion", Veracity "data uncertainty" — plus "More Vs: Value, Volatility, Validity" (p. 9), not by a size: no slide gives a byte threshold.

Lessons 1 2 See also: Volume, Variety, Velocity, Veracity, paradigm shifts

block (HDFS)

The unit in which HDFS stores a file: 64 MB on the slides, 128 MB since Hadoop 2, each kept in 3 copies by default — a 1 TB file takes 3 TB of disk. The first copy goes to the writer's node, the second to a node on a remote rack, the third to another node of that remote rack (p. 857); a reader uses the nearest copy, and a checksum guards every 512 bytes.

Lesson 31 See also: HDFS, replication factor, NameNode

Bloom filter

A "Compact way of representing a set of items" (p. 447): a bit array and k hash functions. Insert sets the k bits of a key; a check answers "maybe" if all k are set and "no" if any is 0, so "Never false negatives" but "Some probability of false positives". Cassandra keeps one per SSTable to skip the files that cannot hold a key.

Lesson 22 See also: SSTable

bool query

The compound query with four arrays (pp. 603, 1653): must — required and scored (AND); filter — required, score ignored; should — optional clauses that add score, an OR only when the bool has no must and no filter; must_not — excluded, not scored (NOT). A document's score is the sum of its must and matching should scores. In the papers' wording, "includes the words" is must, "must not affect the final score" is filter, "prioritising" or "assigning a higher score" is should.

Lesson 26 See also: filter context, leaf query clause, match query

Boyce–Codd normal form (BCNF) BCNF; 3.5NF

For every dependency X → Y, either Y ⊆ X (trivial) or X is a superkey (p. 139). It is stricter than 3NF and the last rung the course climbs; 4NF and 5NF follow on the ladder.

Lesson 9 See also: third normal form (3NF), functional dependency

BSON Binary JSON

How MongoDB stores documents: "Data stored as BSON (Binary JSON)", "used for speed" (p. 299). "Each entry consists of a field name, a data type, and a value", and large elements are prefixed with a length so that a reader can skip them (p. 301). It has more types than JSON, such as dates and ObjectIds.

Lesson 13 See also: JSON, document

Back to the letters
cache

"Data duplicating original values stored elsewhere or computed earlier" (p. 367). A request that finds its key is a hit, one that does not a miss; the hit ratio is hits over all requests. A cache pays when its hit ratio exceeds the cost of a look over the cost of the original, \(h \gt t_c / t_o\): the slide's "more cache hits then cache misses" (p. 371), \(h \gt 0.5\), is only the case of a look costing half a trip. A cold cache is empty, a warm one holds what the requests ask for.

Lesson 19 See also: cache-aside, invalidation, replacement policy, memcached

cache-aside lazy loading

The usual way to use a cache: look up the key; on a miss, query the database or compute the value, store it in the cache, return it. The name is not on the slides, which show the pattern in code.

Lesson 19 See also: cache, invalidation

CAP theorem Brewer's theorem

Of consistency, availability and partition tolerance, a distributed system cannot guarantee all three. The slide's "A distributed system can satisfy any two of these guarantees at the same time but not all three" (p. 195) is misleading, and the next slide corrects it (p. 196): partitions will happen, so while one lasts the system chooses consistency (CP: it answers correctly or with an error) or availability (AP: it answers, possibly with stale data); "CA" makes sense only on a single site.

Lessons 5 16 20 See also: consistency (CAP), availability, partition tolerance, BASE

Cassandra Apache Cassandra

A wide-column store "originally designed at Facebook", now an Apache project (p. 410): "cassandra ~= bigtable + dynamo" (p. 411) — Bigtable's sparse-map data model on Dynamo's ring, with no master at all. It favours availability and partition tolerance with eventual consistency, "tuneably" per operation (pp. 400, 438), and has no joins and no referential integrity: data is denormalised and duplicated.

Lessons 20 21 22 See also: keyspace, column family, partition key, consistent hashing, CQL

Catalyst

Spark SQL's optimizer, which keeps a query as a tree and rewrites it with rules — a rule finds a pattern and replaces it, as constant folding turns 1 + 2 into 3. Four phases (p. 1278): analysis resolves the attributes against the catalog; logical optimization applies rules such as predicate pushdown and projection pruning; physical planning generates plans and a cost model picks one; code generation compiles it, with Scala quasiquotes, into code that runs as RDD operations.

Lessons 38 40 See also: predicate pushdown, projection pruning, Spark SQL

censored data censoring; truncated data

A censored value is "bounded but not precise": "Call duration > 20 are recorded as 20" — the record stays, its value replaced by the bound. A truncated value is dropped: "customers with less than 2 minutes of calling per month" — the record is gone. An interval is left censored when its start is unknown, right censored when it is still running at the end; the metadata should record both kinds.

Lesson 36 See also: missing values, outlier

chunk

A contiguous range of shard-key values, together with every document whose key falls in it: the unit that is split and moved. A split cuts a chunk in two and moves no document; a migration, decided by the balancer, moves a whole chunk to another shard. The slide's maximum of 64 MB was the default up to MongoDB 5.0; it is 128 MB since 6.0, and the current manual calls a chunk a range.

Lesson 16 See also: shard key, shard

client.search

The Milvus client call for a similarity search: client.search(collection_name=…, data=[query_vector], limit=5, filter='name like "Mic%"', output_fields=[…], group_by_field="…"). The filter acts before the ranking; with group_by_field each group returns its most similar entity and limit counts groups. A vector search with a scalar filter is what the session calls a hybrid search (the Milvus documentation: filtered search). The paper of 11 February 2025 asks to fill in such a call.

Lesson 28 See also: Milvus, vector database

clustering key clustering column

In Cassandra, the columns of the PRIMARY KEY after the partition key: "It is used to define the way data is stored within a partition (i.e., the sorting)" (p. 1560). In PRIMARY KEY (a, b, c) rows of one partition are sorted by b, then c; WITH CLUSTERING ORDER BY (b DESC) reverses it. In Snowflake a clustering key (CLUSTER BY (col)) is something else: the columns that order a very large table's micro-partitions, so that queries can skip most of them.

Lessons 21 23 See also: partition key, CQL, Snowflake

collect()

The Cypher aggregate that packs the values of a group into one list — the answer to "return the collection of": MATCH (l:Listing)-[:IN_NEIGHBORHOOD]->(n:Neighborhood) RETURN n.name, collect(l.name) gives one row per neighbourhood with the list of its listings' names (p. 1411). Like count(), it groups by the other, non-aggregated items of its WITH or RETURN; with none, it makes a single list. In Spark collect() is something else: an action that copies a whole RDD or DataFrame into the driver.

Lesson 12 See also: grouping key, WITH, action

collection

In MongoDB, a bag of documents, the counterpart of a table: the documents may share their fields, but nothing forces them to (p. 302). In Milvus, "the logical container for our vectors", whose dimension must match the vectors (p. 1704). In CQL a collection is a column type that holds several values: list<T>, set<T>, map<K, V>.

Lessons 13 21 28 See also: document, MongoDB, Milvus

column family CF; table (CQL)

A sparse table of records of a similar kind (p. 416), in CQL simply a table — TABLE and COLUMNFAMILY are interchangeable. Each row, found by its key, holds only the columns it has; a column is a name (sorted by the family's comparator, used in queries), a value (not queried) and a timestamp (last write wins). In HBase a column family is a group of columns declared with the table and stored apart, the columns written family:qualifier.

Lessons 20 21 32 See also: keyspace, super column, wide-column store

column store column-oriented database; columnar storage

A layout that keeps each column in a piece of its own, while a row store keeps each record in one piece (p. 402): a query that needs a few columns reads only those — "suitable for read-mostly, read-intensive, large data repositories" — and equal neighbouring values compress well, for example by run-length encoding, a run stored as (value, start_pos, run_length). The price is writes and tuple reconstruction: one record touches every column.

Lessons 5 20 22 See also: wide-column store, OLAP, Parquet

combiner

An optional mini-reduce run on each map task's output before the shuffle, so that only partial results travel: the word count sends ⟨store, 4⟩ instead of four ⟨store, 1⟩. "Input types must be the same as output types" (p. 799), because the reducer must accept combined and raw pairs alike. The framework may run it zero, one or several times, so it must have no side effects and the result must not depend on how often it ran: a sum, a count or a maximum pass, an average does not — carry (sum, count) pairs instead. Spark's reduceByKey applies one automatically on the map side.

Lessons 30 39 See also: MapReduce, shuffle, reduceByKey

conceptual design

The first of the three levels of database design (p. 63): "Constructing an information model, independent from all physical consideration" — its product is an ER diagram. Logical design then builds the database on a specific data model (tables, a graph, documents, column families); physical design implements it with storage structures and access methods.

Lesson 6 See also: ER diagram

config servers

The servers that store "cluster chunk ranges and locations" (p. 326): the map from every chunk to its shard, the cluster's one source of truth. The slide's "only 1 or 3" is out of date: since MongoDB 3.4 they must form a replica set.

Lesson 16 See also: mongos, chunk

consistency (ACID) the C of ACID

"The transaction satisfies the integrity constraints": if the initial state is consistent, the final state is consistent too (p. 190); the intermediate states do not count. It is a different property from the C of CAP, which is about copies agreeing.

Lesson 3 See also: ACID, consistency (CAP), integrity constraint

consistency (CAP) the C of CAP

"All nodes see the same data at the same time" (p. 195): every read returns the latest write, whichever copy answers. Not to be confused with the C of ACID.

Lesson 5 See also: CAP theorem, consistency (ACID), eventual consistency

consistency level CL

How many replicas must answer a Cassandra read or write, chosen per operation (p. 450): ANY (any node, a hint counts; writes only), ONE, QUORUM, LOCAL_QUORUM (in the coordinator's datacenter), EACH_QUORUM, ALL. It makes Cassandra "tuneably consistent": ONE keeps working while replicas are down but may read a stale value; QUORUM and ALL fail when too few replicas answer, and when the replicas read and written overlap, \(R + W \gt N\), a read always sees the last write.

Lessons 20 21 22 See also: quorum, eventual consistency, hinted handoff

consistent hashing hash ring; token ring

Nodes and keys are hashed onto the same circle, and a key belongs to the first node clockwise from its token. A node that joins takes one arc from one neighbour, while a hash modulo the number of nodes would move almost every key. In Cassandra the other N − 1 copies go to the next nodes clockwise (Simple Strategy, one datacenter) or to different racks, with a replication factor per datacenter (Network Topology Strategy). The Cassandra slides draw the ring without naming it; the name appears on the Twemproxy slide, which "Supports consistent hashing" (p. 363).

Lessons 19 22 See also: partitioner, replication factor, Twemproxy

control chart

A tool from the quality control of production lots: plot an aggregate of each sample, such as its mean (an X-bar chart), against the expected value and control limits — the mean ± 3 standard errors — and call a point beyond them "Out of Control" (p. 1122). For two correlated variables the rectangle of two charts misses some alarms and raises false ones; the ellipse of equal Mahalanobis distance does not.

Lesson 36 See also: outlier

cosine similarity

The cosine of the angle between two vectors, \(\cos\theta = A \cdot B \,/\, (\lVert A\rVert\,\lVert B\rVert)\): 1 when they point the same way, 0 when orthogonal, −1 when opposite. The inner product \(A \cdot B\) is its numerator alone, so it grows with the lengths; the Euclidean distance measures the gap between the tips. For unit vectors all three rank alike, since \(\lVert A - B\rVert^2 = 2 - 2\cos\theta\). A similarity is largest for the best match; the cosine distance \(1 - \cos\theta\) is smallest.

Lessons 24 27 28 See also: embedding (vector), k-nearest-neighbour search, TF-IDF

CQL Cassandra Query Language

Cassandra's SQL-like language, "similar to SQL syntax but limited (no joins, limited aggregations)" (p. 1551), typed at the cqlsh prompt. Every INSERT and UPDATE is an upsert: a row with the same primary key is overwritten, not refused. A user-defined type (CREATE TYPE) is a named record used as a column type, often as list<frozen<t>>; SOURCE 'file'; runs a file of statements.

Lesson 21 See also: partition key, clustering key, ALLOW FILTERING, Cassandra

Cypher

Neo4j's query language: declarative, it "focuses on the clarity of expressing what to retrieve from a graph, not on how to retrieve it" (p. 1383), and its patterns are ASCII art — nodes in round brackets, relationships as arrows. Keywords are written in capitals: MATCH, WHERE, WITH, RETURN.

Lessons 11 12 See also: Neo4j, pattern, MATCH

DAG scheduler DAGScheduler

When an action runs, the DAGScheduler takes the graph of RDDs built by the transformations — a directed acyclic graph — and will "split graph into stages of tasks" at the wide dependencies, pipelining the narrow functions inside each stage (p. 1225). The TaskScheduler then launches one task per partition through the cluster manager, where the data already is, and retries failed or straggling tasks.

Lessons 38 39 See also: stage, narrow and wide dependencies, action

data cleansing data scrubbing

"The act of detecting and correcting (or removing) corrupt or inaccurate records from a data set" (p. 1084). In practice it runs five steps (p. 1086): parsing the fields, correcting them against other sources, standardising their form, matching the records that describe the same entity, and consolidating them "into ONE representation" (p. 1096). Consolidating merges: the record of p. 1097 keeps values from both sources, while the course notes' "one of them is discarded" would lose some.

Lesson 35 See also: data wrangling, data quality, duplicates problem

data cube Datacube; Multidimensional Cube; OLAP cube

The facts seen as points in a space whose axes are the dimensions: every cell holds the measure of one combination of values, like Store × Product × Time (p. 514). Roll-up, drill-down, slice and dice are its operations (p. 513). ROLAP keeps the cube in relational tables, MOLAP in arrays.

Lesson 23 See also: roll-up, drill-down, slice and dice, dimension

data drift and concept drift

Two reasons a deployed model degrades although nobody touched the code. Data drift: the distribution of the inputs changes, \(P(X)\) moves — this year's applicants are younger. Concept drift: the relation between inputs and target changes, \(P(Y \mid X)\) moves. The slides use both words without defining them.

Lesson 29 See also: MLOps, training-serving skew

data-driven virtuous cycle value cycle

The loop of p. 38: Data Ingestion → Data Analysis → Value Generation → back to ingestion. The value that the analysis produces pays for collecting more data; pp. 40–42 turn the loop into a method: collect, analyse, build value.

Lesson 1 See also: data ingestion

data engineer

The role that builds "the underlying system that allows Data Scientist to analyze, develop and deploy" models, handling "the lifecycle of data in a processing pipeline, ensuring that it is always available and usable by whoever needs it". The data scientist then turns the data into actionable insights, data products and business stories. No slide defines the two roles; the course notes do (section 2.3).

Lesson 1 See also: data-driven virtuous cycle

data ingestion

"The process of importing, transferring and loading data for storage and later use" (p. 159), from a variety of sources, possibly changing the files into a format that optimises storage. It is the first circle of the data-driven cycle.

Lessons 1 3 See also: data wrangling, data-driven virtuous cycle

data lake

One centralised reservoir that receives structured and unstructured data in raw form, on which all the analytical jobs run; the schema is applied when the data is read (p. 172). Without organisation and indexing it becomes a data swamp, where nobody can find anything (course notes).

Lesson 4 See also: schema on read, zones

data locality

"Moving Computation is Cheaper than Moving Data" (p. 837): the MapReduce master asks the NameNode where the blocks of the input are and runs each map task on a node that stores its split, or failing that on one nearby, behind the same switch — which "conserves network bandwidth" (p. 822). Spark's scheduler does the same with partitions.

Lessons 30 31 39 See also: MapReduce, HDFS, NameNode

data munging

"Potentially lossy transformations applied to a piece of data or a file"; "Vague data transformation steps that are not yet completely clear" — removing punctuation or HTML tags, parsing, filtering (p. 1102). A column of numbers needs a meaning — its unit, its source — before it can be munged safely.

Lesson 36 See also: data wrangling, data cleansing

data quality

The conventional definition (p. 1069) has five dimensions: accuracy ("The data was recorded correctly"), completeness ("All relevant data was recorded"), uniqueness ("Entities are recorded once"), timeliness ("The data is kept up to date") and consistency ("The data agrees with itself"). The next slide calls it unmeasurable, context independent, incomplete and vague; bad data feeds a vicious cycle of wrong analyses, insights and decisions.

Lesson 35 See also: Veracity, data cleansing, data wrangling

data stream stream

An unbounded sequence of data items arriving over time: in Storm, an "Unbounded sequence of tuples" (p. 927), a tuple being a named list of values such as (word: "fresh"). Since nobody can wait for the end, a streaming query stays registered and looks at limited windows of the data — the clicks of the last minute.

Lessons 1 33 See also: Storm, topology, Velocity

data warehouse DW; DWH

"A subject-oriented, integrated, time-varying, non-volatile collection of data that is used primarily in organizational decision making" (Inmon, p. 494). Unlike the query-driven approach, which asks the sources through wrappers at question time, it integrates the data in advance (p. 490), so queries are fast and history is kept, though not necessarily current. A data mart is a departmental subset of it (p. 504).

Lesson 23 See also: query-driven approach, OLAP, ETL, star schema, Snowflake

data wrangling

"The process of transforming 'raw' data into data that can be analyzed to generate valid actionable insights" (p. 1080). Lesson 3 gives the four boxes of p. 160 — understand, cleanse, augment, shape; lecture 14 the steps Obtain, Understand, Explore, Transform, Augment, Shape, run in a loop.

Lessons 3 35 37 See also: data cleansing, data ingestion, data munging

DataFrame

"A distributed collection of rows organized into named columns" (p. 1246), formerly SchemaRDD: an RDD with a schema, "Immutable Data with named columns (built on RDDs)" (p. 1216). Because Spark sees the columns and the expressions, Catalyst and Tungsten can optimise the plan, and DataFrame code runs equally fast from Python, Scala, R or SQL. In Scala a DataFrame is a Dataset of Row objects; a typed Dataset holds JVM objects.

spark.createDataFrame(rows, ["Hospital_ID", "Name"]) builds one from Python tuples, inferring the types (or pass a StructType schema). Being immutable, it never changes in place: to add one row, build a one-row DataFrame with the same columns and write df = df.union(new_row) — the "add one element" of the paper of 30 January 2026.

Lessons 38 39 40 See also: RDD, Spark SQL, Catalyst, groupBy and agg

DataNode

A block server: it stores blocks on its local disks, sends the NameNode a heartbeat every 3 seconds and a report of its blocks, and on a write forwards the packets to the next DataNode of the pipeline. A DataNode that stops beating is declared dead and its blocks are copied elsewhere.

Lesson 31 See also: NameNode, block (HDFS)

definition and repetition levels

How Parquet stores nested records in flat columns: next to each value, its definition level says how many of the optional or repeated fields on its path are present, and its repetition level says at which repeated field the value continues a list, 0 meaning that a new record starts. A level with maximum m takes \(\lceil \log_2(m+1) \rceil\) bits.
