Every box below is the cheat sheet that closes one lesson, in its "Key take-aways", copied here unchanged. A page number in brackets is the page of the slides a row comes from, in the numbering the whole notebook uses: the pages of one file that merges all the lecture and exercise-session decks. What a row marks "not on the slides" or "background" is the notebook's own addition. The heading above each box leads to its lesson, where every row is explained, drawn and tried out.

Lesson 2 · Four ways of solving problems differently

Shift 1
"Leverage more of the data being captured" — traditional: "Analyze small subset of information" (6 of 40 dots); innovative: "Analyze all available information" (40 of 40)
Shift 2
"Data-driven exploration looking for correlation" — traditional: Hypothesis → Question → Data → Answer, "Start with hypothesis and test against selected data"; innovative: Data → Exploration → Correlation → Insight, "Explore all data and identify correlations"
Shift 3
"Reduce effort required to leverage data" — traditional: "Carefully cleanse information before any analysis" (small amount, carefully organized); innovative: "Analyze information as is, cleanse as needed" (large amount, messy)
Shift 4
"Leverage data as it is captured" — traditional: Data → Repository → Analysis → Insight, "after it's been processed and landed in a warehouse or mart"; innovative: Data → Analysis → Insight, "in motion as it's generated, in real-time"
x → nature → y
x independent variable, y response variable; exploration relates x and y without opening "nature" (Breiman's two cultures, background)

\(\binom{N-m}{k}/\binom{N}{k}\): 6 of 40 with 3 defects ≈ 0.61; only \(k \ge N - m + 1\) gives 0
Time to insight
batch every \(T\): \(T/2 + p\) on average, \(T + p\) at worst; in motion: \(p\)
Photo pairs
track gauge vs trackside sensor, Union Pacific (p. 22); lab flask vs chemical plant (p. 28); seismograph vs live trading app (p. 31)
Twins
shift 3 ↔ schema-on-read, "Load data first, ask question later" (p. 170); shift 4 ↔ Velocity, "Data in motion" (p. 7)

Lesson 8 · The relational model and the ER-to-table recipe

Relation
\(r \subseteq D_1 \times \dots \times D_n\); degree \(n\), cardinality = number of tuples; a set: no order, no duplicates
Relational model
named attributes → non-positional; references by key values
Schemas
\(R(A_1, \dots, A_n)\); database schema \(\{R_1(X_1), \dots, R_n(X_n)\}\); instance = current set of tuples
Nulls
unknown · non-existent · no-information (the one DBMSs adopt)
Constraints
predicates; intra (domain, tuple, keys) · inter (referential)
Superkey
\(t_1[K] = t_2[K] \Rightarrow t_1 = t_2\)
Key
minimal superkey; several possible; schema-level
Primary key
chosen key, no nulls, underlined: Sale(SaleID, Date, Amount)
Referential constraint
every value of X in R1 appears as a PK value of R2; directional; composite = whole pair
Foreign key (SQL)
FOREIGN KEY (Registration, Dept) REFERENCES Cars (Registration, Dept)
Posted foreign key
column with the other entity's key, marked *: Sale(…, Cust-ID*)
Load
non-null values in the column / rows of the table
Step 1
entity → table; attribute → column; instance → row
Max rule
post into a "1" side, NEVER into an "N" side (repeating groups)
Min rule
post into a mandatory side (no nulls); may be violated
Step 2
(x,N)-(x,N) → separate table, PK = both keys, no exceptions
Step 3
(1,1)-(1,1) → merge, or post one way; never both; no separate table
Step 4
one (1,1) side → foreign key INTO the (1,1) table; no separate table
Step 5
(0,1) sides → high load: post into the (0,1) (5A); low: separate table keyed by the (0,1) side (5B); (0,1)-(0,1): higher load if high
Relationship attribute
in the separate table, or next to the posted foreign key
Redundancy
one fact in multiple places or multiple facts in one place

Lesson 9 · Normal forms: the key, the whole key, nothing but the key

Functional dependency X → Y
any two rows that agree on X agree on Y, "at any given time" (p. 123); X is the determinant
Key, superkey
a key determines every column; X is a superkey iff \(X^+\) = all columns; a candidate key is a minimal superkey
Closure \(X^+\)
start from X, add the right side of every FD whose left side is inside, repeat; X → Y follows iff \(Y \subseteq X^+\)
Full / partial / transitive
the arrow starts at the whole key / at part of a composite key / at a non-key column
1NF
atomic values, no repeating groups, a primary key; "All relations are in 1st Normal Form"
2NF
1NF + no partial dependencies (automatic when every candidate key is one column)
3NF
2NF + no transitive dependencies; general form: for every non-trivial X → A, X is a superkey or A is part of a candidate key
BCNF ("3.5NF")
for every X → Y: trivial (Y ⊆ X) or X a superkey
Repair recipe
the determinant becomes the primary key of a new table with its dependents and stays as a foreign key in the old one (p. 136)
Anomalies
update (change every copy), insertion (a fact needs an unrelated one), deletion (one fact takes another with it)
Ladder (p. 138)
1NF → 2NF → 3NF → BCNF → 4NF → 5NF; the course stops at BCNF
Pine Valley in 3NF
ORDER_LINE(Order_ID*, Product_ID*, Ordered_Quantity), PRODUCT, ORDER(Order_ID, Order_Date, Customer_ID*), CUSTOMER

Lesson 11 · Cypher: nodes, relationships, patterns and paths

Node pattern
(n:Person:Manager {name: "Mark"}) — variable, labels, properties; () any node
Relationship pattern
-[r:KNOWS {since: 2015}]-> — one type; <-[ ]- reverse, -[ ]- either way
Colon rule
[r] any type · [:TYPE] type filter · [r:TYPE] both
CREATE
always writes; relationship: direction + exactly one type
MERGE
match the whole pattern or create it; ON CREATE SET …
SET / REMOVE
SET n.p = v, SET n:Label, REMOVE n:Label
DELETE
MATCH … DELETE r; a node only without relationships
DETACH DELETE
relationships first, then the node; MATCH (n) DETACH DELETE n empties the graph
Rows
one per path; RETURN DISTINCT x, count(DISTINCT x) for things
Relationship uniqueness
a relationship at most once per path; nodes may repeat
PROFILE / EXPLAIN
run + plan with rows and db hits / plan only, estimates
Variable length
[*] 1 or more · [*0..] 0 or more · [:R*1..3] 1 to 3 R; always bound
Shortest paths
p = shortestPath((a)-[*..6]-(b)) one · allShortestPaths(…) all
Path functions
nodes(p), relationships(p), length(p), all(x IN list WHERE …), any, none
Planner
condition on every element → fast bidirectional BFS; needs the whole path → exhaustive DFS fallback; after WITH p → no fallback

Complete records

mean, median; assumes missing values distributed like the observed ones; ignores inter-relationships; introduces bias; easy
Monotone pattern
"all prior attributes are populated": a staircase of holes
Regression method
\(X_3 = a + b X_2 + c X_1\); \(X_4 = d + e X_3 + f X_2 + g X_1\); sweep left to right
