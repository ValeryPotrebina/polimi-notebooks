Лаба 2. Шесть попыток победить overfitting

46 тем, и accuracy молчит

Данные лабы — 11 228 коротких новостей агентства Reuters, у каждой одна тема из 46. Темы очень неравны: earn (отчёты о прибыли) — 3 972 статьи, 35 % всех, а у heat, lei и silver по 16. Перекос 248 : 1.

Статья хранится как список рангов слов: 1 — самое частое слово коллекции, 2 — следующее. Сети нужен вход фиксированной длины, и статья становится multi-hot вектором (multi-hot encoding): 2 000 столбцов, по одному на самые частые слова, с единицей там, где слово встречается.

X = np.zeros((len(sequences), VOCAB_SIZE), dtype=np.float32)
for i, sequence in enumerate(sequences):
    ranks = np.array(sequence)
    X[i, ranks[ranks <= VOCAB_SIZE] - 1] = 1.0   # rank 1 goes to column 0
y = labels.astype(np.int64)
  • ranks <= VOCAB_SIZE оставляет только словарь. Эти 2 000 слов покрывают 86 % всех слов коллекции, в средней статье их 67 разных. Порядок слов и повторы теряются.
  • astype(np.int64) — CrossEntropyLoss ждёт номера классов типа int64. Входы — нули и единицы одного масштаба, scaler не нужен.

Два вызова train_test_split(..., stratify=...) делят статьи на 7 858 / 1 685 / 1 685: training, validation и test (урок 18). stratify сохраняет доли тем, и даже тема из 16 статей получает 2–3 статьи в validation, а не выпадает из validation целиком.

«Словарь из 2 000 слов ничего не знает о test». Знает: ранги — это частоты слов во всей коллекции, вместе с test. Утечка крошечная и без меток, но в своём проекте словарь строят только по training set.

Возьми «классификатор», который на любую статью отвечает earn: majority = np.full_like(labels, counts.argmax()). Его accuracy — 0.354, угадана каждая третья статья. Weighted F1 — 0.185. Macro F1 — 0.011.

Macro F1 (macro-averaged F1) считает binary F1 из урока 1 для каждой темы отдельно — «эта тема против всех остальных» — и берёт простое среднее:

\[ F_1^{\text{macro}} = \frac{1}{46}\sum_{k=1}^{46} F_{1,k} \]

Weighted F1 усредняет те же 46 чисел с весами — долями тем, и earn весит в нём 35 %. У нашего «классификатора» F1 темы earn равен 0.523 (precision 0.354, recall 1), у остальных 45 тем — ноль. Отсюда 0.523 / 46 = 0.011 и 0.354 · 0.523 = 0.185.

В функции score это f1_score(y_true, y_pred, average='macro', zero_division=0). Темы, которые модель ни разу не назвала, входят в среднее с F1 = 0: верных ответов у них нет. zero_division=0 только ставит 0 вместо их precision 0/0 и глушит предупреждение. За macro F1 следят и early stopping, и выбор модели (METRIC = 'f1').

Macro F1 — среднее F1 по темам: тема из 16 статей весит в нём столько же, сколько earn из 3 972.

Сеть, цикл и одна изменённая строка

Сеть — FeedForwardNet, обычный MLP (урок 9):

layers, width = [], in_features
for _ in range(hidden_layers):
    layers += [nn.Linear(width, hidden_size), nn.ReLU()]
    if dropout_rate > 0:
        layers.append(nn.Dropout(dropout_rate))
    width = hidden_size

# Output layer: one logit per class
layers.append(nn.Linear(width, num_classes))
self.net = nn.Sequential(*layers)

Три скрытых слоя по 512 ReLU и выход на 46 чисел. Softmax в сети нет: forward возвращает logits (логиты), а CrossEntropyLoss сам применяет log-softmax (уроки 11 и 15). Параметров 1 573 422 — около двухсот на обучающую статью: сеть нарочно велика, чтобы было чем переобучаться (урок 17). Слои nn.Dropout появляются только при dropout_rate > 0, и номера модулей от этого сдвигаются — это всплывёт при загрузке весов.

Шесть экспериментов отличаются одной строкой, а честность сравнения держит make_model:

def make_model(dropout_rate=0.0):
    """Build a fresh network; reseeding gives every experiment the same initial weights."""
    torch.manual_seed(SEED)
    return FeedForwardNet(input_features, HIDDEN_LAYERS, HIDDEN_SIZE, num_classes, dropout_rate).to(device)

Первый эффект torch.manual_seed(SEED) — одинаковые начальные веса у всех шести прогонов. Второй менее заметен: DataLoader с shuffle=True берёт seed перемешивания из того же глобального генератора. Поэтому у прогонов без dropout совпадают и батчи всех эпох, а у dropout-прогонов, чьи маски тянут числа из того же генератора, — только порядок первой эпохи.

Одна эпоха обучения — train_one_epoch без ветки L1-штрафа и без сбора ответов для метрики:

model.train()                                    # (1)
for x, y in loader:
    x, y = x.to(device), y.to(device)
    logits = model(x)
    loss = criterion(logits, y)
    penalty = 0.0
    if l2_lambda > 0:                            # (2)
        penalty += l2_lambda * sum(p.pow(2).sum() for p in model.parameters())
    optimizer.zero_grad()                        # (3)
    (loss + penalty).backward()
    optimizer.step()
    total_loss += loss.item() * x.size(0)        # (4)
  1. model.train() включает dropout (а batch normalization, будь она в сети, переводит на статистики батча); evaluate переключает сеть в eval(), и без этой строки все эпохи после первой молча шли бы без dropout.
  2. L2-штраф (о нём ниже) минимизируют, но не записывают: кривые всех прогонов меряют один и тот же loss.
  3. zero_grad() стирает градиенты прошлого шага: PyTorch накапливает их в .grad, и без этой строки шаг шёл бы по сумме всех прошлых (урок 43).
  4. loss — среднее по батчу; умножение на x.size(0) и деление на len(loader.dataset) дают среднее по статьям, ведь последний батч — 18 статей.

evaluate — тот же проход без обновлений: model.eval() выключает dropout, with torch.no_grad(): не строит граф для backward (на числа это не влияет), ответ — logits.argmax(dim=1): softmax порядок логитов не меняет.

«Training F1 на графике — это насколько сеть выучила training set». Не совсем: train_one_epoch считает его по ходу эпохи — в режиме train() и на весах, которые за эпоху 246 раз меняются. Из-за смены весов validation loss на первой эпохе ниже training loss (1.15 против 1.52): в среднее вошли первые батчи, когда сеть ещё ничего не умела. Из-за режима train() dropout-прогон пишет на 30-й эпохе training F1 0.87, хотя веса его 29-й эпохи дают на training set 0.963 в режиме eval() — и 0.884 с включённым dropout. Честное сравнение — evaluate(model, train_loader, criterion, device, metric) после эпохи.

Baseline и early stopping — один и тот же прогон

Baseline обучает torch.optim.Adam с lr=1e-3 (это \(\eta\) урока 27) 100 эпох без всякой регуляризации. Training set выучен к 8-й эпохе (training F1 0.93). Validation loss минимален на 2-й эпохе (0.989) и дальше растёт до 3.42, а validation macro F1 с 8-й эпохи стоит около 0.5: 0.533 на 8-й, лучший 0.540 на 59-й, 0.530 в конце. Классический overfitting по loss, а validation F1 при этом не падает: загадка из начала урока.

Early stopping (урок 20) в PyTorch пишут сами; в fit это несколько строк:

best_score, best_state, wait = -np.inf, None, 0
for epoch in range(1, epochs + 1):
    ...  # train_one_epoch, evaluate
    if val_score > best_score:                          # (1)
        best_score, wait = val_score, 0
        best_state = copy.deepcopy(model.state_dict())  # (2)
    else:
        wait += 1
    stop = patience > 0 and wait >= patience            # (3)
    if stop:
        break
if patience > 0:
    model.load_state_dict(best_state)                   # (4)
  1. Рекорд — строго лучше прежнего, как в уроке 20, только здесь ищут максимум macro F1, а не минимум ошибки: отсюда старт с -np.inf.
  2. state_dict() отдаёт ссылки на живые тензоры модели. Без deepcopy каждый следующий optimizer.step() менял бы и «лучшее состояние», и откат вернул бы веса последней эпохи.
  3. PATIENCE = 20: стоп после 20 эпох подряд без рекорда; при patience=0, как у baseline, — все 100 эпох и веса последней.
  4. Откат к checkpoint — весам эпохи рекорда.

Прогоны baseline и early stopping печатают одинаковые строки до четвёртого знака — все, какие есть у обоих. Причина — make_model: те же веса и те же батчи, а patience до остановки на обучение не влияет. Early stopping — это baseline, остановленный после 49-й эпохи и откатившийся к 29-й (macro F1 0.537).

Baseline нашего прогона, все 100 эпох. Виджет ничего не обучает заново: он прокручивает early stopping из fit по этим кривым, эпоха за эпохой. Выбери, за чем следить, и patience. Жёлтая полоса — эпохи ожидания после последнего рекорда, бледная часть кривых — эпохи, до которых обучение не дошло бы. Наведи курсор на кривую, чтобы прочитать эпоху.

Dropout, L2 и AdamW

Early stopping выбирает checkpoint, но в обучение не вмешивается. Три других средства меняют само обучение, и каждому хватает одной строки.

Dropout (урок 23) включается одним аргументом: make_model(DROPOUT_RATE) с DROPOUT_RATE = 0.5 ставит nn.Dropout(0.5) после каждого скрытого ReLU. Число в скобках — вероятность выключить нейрон (drop probability), а \(p\) урока 23 — вероятность оставить; здесь обе равны 0.5. PyTorch делает inverted dropout: в train() выход обнуляется с вероятностью 0.5, а выжившие умножаются на 2, поэтому в eval() слой пропускает всё как есть (урок 23). Итог — macro F1 0.592, лучший из одиночных средств.

L2-штраф лаба пишет руками — строка (2) в train_one_epoch, с L2_LAMBDA = 1e-4. Это weight decay урока 22:

\[ E(\vb{w}) = \bar L(\vb{w}) + \lambda \sum_q w_q^2 \]

Здесь \(\bar L\) — средний loss батча, а \(\lambda\) = l2_lambda — это \(\gamma\) урока 22. Но значение \(\lambda\) в формулы с другой записью штрафа не переносится: в лабе нет ни ½, ни суммы по примерам, а штрафуются и смещения — model.parameters() отдаёт всё. Тот же штраф даёт torch.optim.Adam(..., weight_decay=2e-4): он прибавляет к градиенту \(2 \cdot 10^{-4}\, w\), производную \(10^{-4} w^2\).

У градиентного спуска такой штраф даёт усадку \(1 - 2\eta\lambda\) за шаг (урок 22). У Adam (урок 27) иначе: градиент штрафа \(2\lambda w\) попадает в \(m\) и \(v\) и делится на \(\sqrt{\hat v}\) вместе с градиентом данных. Если данные о весе молчат — нейрон мёртв или слово редкое, — остаётся один штраф, \(\hat m / \sqrt{\hat v} \approx \sign(w)\), и вес идёт к нулю шагом около \(\eta = 10^{-3}\), какой бы малой ни была \(\lambda\). Это «первый шаг Adam ≈ η·sign(g)» из урока 27 — на каждом шаге.

AdamW (decoupled weight decay, отделённое затухание весов) выносит усадку за нормировку (рис. 3):

\[ w \leftarrow (1 - \eta\lambda)\,w - \eta\,\frac{\hat m}{\sqrt{\hat v} + \varepsilon} \]

Здесь lr = \(\eta\), weight_decay = \(\lambda\) (уже другое число, не l2_lambda), а \(\hat m\) и \(\hat v\) считаются по градиенту одних данных. В лабе это torch.optim.AdamW(model.parameters(), lr=LEARNING_RATE, weight_decay=WEIGHT_DECAY) с WEIGHT_DECAY = 1e-1: каждый шаг умножает все веса на \(1 - 10^{-3} \cdot 0.1 = 0.9999\), снимая 0.01 % при любом градиенте (по умолчанию weight_decay=0.01).

Один вес, два вида затухания

Один вес в float32 под тремя оптимизаторами с настройками лабы: \(\eta = 10^{-3}\), \(\beta_1 = 0.9\), \(\beta_2 = 0.999\), \(\varepsilon = 10^{-8}\); у Adam + L2 \(\lambda = 10^{-4}\), у AdamW weight decay 0.1. Данные тянут вес к 0.02 «пружиной» жёсткости K: градиент данных \(K(w - 0.02)\), старт тоже 0.02. При K = 0 данные о весе молчат — так живут веса мёртвого нейрона и редкого слова. Шкала |w| логарифмическая, 10 эпох — 2 460 шагов; острые провалы кривой — шаги, на которых вес проскакивает ноль.

  1. Режим «никак». Предскажи, прежде чем смотреть: за сколько шагов Adam + L2 опустит вес 0.02 ниже \(10^{-3}\)? Сколько от него оставит AdamW за 10 эпох?
    Что должно получиться

    За 23 шага. Градиент штрафа \(2\lambda w\) крошечный, но Adam делит его на его же масштаб, \(\sqrt{\hat v}\), и шаг выходит около \(\eta = 0.001\) — как будто \(\lambda\) огромна. На 25-м шаге вес проскакивает ноль и дальше колеблется вокруг него, меняя знак, а размах колебаний тает экспоненциально. AdamW за 2 460 шагов умножает вес на \(0.9999^{2460} \approx 0.78\): остаётся 0.0156.

  2. Переключай «слабо», «наравне со штрафом» и «крепко». Где к концу окажется вес у Adam + L2 и у AdamW?
    Что должно получиться

    Adam + L2 приходит туда, где градиент данных уравновешивает штраф, \(K(w - 0.02) + 2\lambda w = 0\): 0.0018 при «слабо», 0.0100 «наравне», около 0.020 при «крепко». AdamW держит 0.0200 во всех трёх режимах: нормировка Adam превращает даже слабый градиент данных в шаг порядка \(\eta\), а усадка — всего 0.01 % за шаг. Вес, который данные крепко держат, почти не замечает ни того, ни другого; разница — у тех, кого данные защищают плохо.

  3. Режим «никак»: веди шаг k от 1 500 к концу. Где у Adam + L2 |w| впервые меньше \(1.2 \cdot 10^{-38}\), и что с весом дальше?
    Что должно получиться

    Впервые на шаге 1 538. Это граница обычных (normal) чисел float32, ниже идут subnormal-числа с меньшей точностью. Вес ещё несколько десятков шагов скачет вокруг нуля, а с шага 1 607 замирает на \(-7.2 \cdot 10^{-40}\): PyTorch сначала умножает \(\hat m\) на \(\eta\), и у такого веса это произведение меньше самого маленького числа float32, \(1.4 \cdot 10^{-45}\). Оно округляется до нуля, а с ним и весь шаг. Ровно нулём сам вес так и не становится. Почему это важно для скорости — в ловушке ниже.

В L2-модели нашего прогона по модулю меньше \(10^{-3}\) от 29 до 56 % весов каждого слоя (у остальных моделей 0.6–2.7 %), а 11 % всех параметров меньше \(10^{-38}\). В третьем скрытом слое мертвы 207 нейронов из 512 (урок 24; у baseline 139), и у 165 нейронов этого слоя все входящие веса меньше \(10^{-3}\). В первом слое чаще всего гаснут веса редких слов: данные защищают их реже всего.

«L2-прогон медленный, потому что штраф считается в Python». Нет: он шёл 43 мин 32 с на 48 эпох, в 8 раз дольше на эпоху, чем baseline. Числа меньше \(1.2 \cdot 10^{-38}\) float32 хранит как subnormal, и арифметика с ними на CPU в разы медленнее. В нашей проверке шаг обучения от финальных весов L2-модели занял 99 мс против 37 мс у baseline, а после torch.set_flush_denormal(True), которая заменяет subnormal-числа нулями, — 31 мс. Adam(weight_decay=2e-4) упёрся бы в то же: дело в нормировке Adam, а не в записи штрафа. Лекарства — та же set_flush_denormal(True) или AdamW: прогон AdamW шёл 7 с на эпоху, как baseline.

«Разница 0.02 в macro F1 — это разница методов». В validation у 11 тем не больше трёх статей, и одна статья такой темы, сменившая ответ, двигает macro F1 на 0.7–1.4 пункта. На test порядок моделей без dropout меняется: худший из них на validation, baseline, выходит первым (0.538), а второй по validation, L2, — последним (0.477). И каждое средство взято в одной, неподобранной дозе, так что «AdamW лучше L2» сравнивает две случайные силы, а не два метода. Честно мерить разницу — работа cross-validation и нескольких seed, это лаба 3 (урок 45).

Прогон на GPU в Colab или с другим seed даст другие числа: лучшие эпохи, сотые доли F1, порядок early stopping, L2 и AdamW, время. Устойчиво то, что следует из механики: training set выучен за десяток эпох при растущем validation loss и стоящем F1; регуляризация сдерживает loss; у L2 самые мелкие веса, у выхода baseline — самые крупные; Adam + L2 гасит веса, которые данные не защищают. Лидерство dropout правдоподобно, но и оно — одно разбиение и один seed.

Сохранение и новый текст

Остаётся сохранить победителя и спросить его о новом тексте:

# Load them into a new network: the architecture must match, dropout layers included

  • Имена ключей — номера модулей в nn.Sequential (рис. 2), и make_model() без dropout этот файл не примет: RuntimeError о missing и unexpected keys. Поэтому next(...) достаёт drop probability из самой модели.

Новый текст encode кодирует как статьи: слова — в ранги через word_index, ранги — в multi-hot по тому же словарю; слова вне словаря отбрасываются. Дальше:

unsqueeze(0) делает из вектора [2000] батч из одной статьи, [1, 2000]; softmax нужен только чтобы показать вероятности. Без loaded_model.eval() dropout остался бы включён, и каждый вызов шёл бы через новую прореженную сеть: в нашей проверке пять вызовов подряд дали этой фразе trade от 0.04 до 0.97.

Разгадка: loss растёт от уверенности

По macro F1 спор двух моделей из начала решается сразу: 0.256 у эпохи 2 против 0.530 у эпохи 100. Откуда разница — видно по темам.

После эпохи 2 у 25 тем из 46 нет ни одного верного ответа, к сотой — у 6. Десять крупных тем почти не меняются (средний F1 0.72 оба раза), а остальные 36 растут с 0.13 до 0.48. Эпохи, в которые loss «портится», — это эпохи, когда сеть учит редкие темы, а accuracy этого почти не видит.

Почему же растёт loss? Cross-entropy штрафует \(-\ln p\) верной темы, а accuracy и F1 смотрят только на argmax. RMS выходных весов за 100 эпох вырастает с 0.026 до 0.40, логиты — вместе с ним, softmax насыщается, и ошибки сеть делает почти наверняка: у 152 из 357 ошибок на validation вероятность неверной темы больше 0.99. Самая дорогая статья стоит 155 nats, а 98 % validation loss дают неверные ответы. Это over-confidence (самоуверенность), и её можно измерить, не тронув ни одного ответа.

Те же ответы, другой loss

Три финальные модели нашего прогона. Все логиты модели умножаются на одно число s, и для каждого s заново считается validation cross-entropy; при s = 1 это тот loss, который печатал fit. Argmax от умножения на положительное число не меняется, поэтому ответы, accuracy и macro F1 одинаковы при любом s. Шкала s логарифмическая.

  1. Сейчас s = 1 — логиты такие, какими их выдаёт сеть. Предскажи: если все логиты baseline уменьшить примерно в пять раз (s ≈ 0.2), loss вырастет или упадёт? Изменится ли хоть один ответ? Сдвинь ползунок.
    Что должно получиться

    Loss падает с 3.42 до 1.31 (s = 0.194), а ответов не меняется ни одного: macro F1 остаётся 0.530. Почти две трети loss baseline — не неверные ответы, а лишняя уверенность в них.

  2. Найди минимум каждой кривой. Чьи логиты приходится ужимать сильнее всего?
    Что должно получиться

    Baseline — 1.31 при s ≈ 0.19, его логиты надо ужать впятеро. Early stopping — 1.16 при s ≈ 0.3 (втрое), AdamW + dropout — 1.00 при s ≈ 0.45 (примерно вдвое). Все три слишком уверены; регуляризация это уменьшает, но не убирает. И даже при лучшем s регуляризованные модели ниже: одной общей уверенностью разница не исчерпывается.

  3. Уведи s к 0.01. Почему все кривые приближаются к пунктиру ln 46?
    Что должно получиться

    При s → 0 все логиты стремятся к нулю, softmax даёт каждой из 46 тем 1/46, и cross-entropy стремится к ln 46 = 3.83 — у любой модели. А ответы всё те же: argmax крошечных логитов прежний.

Отсюда главный вывод лабы. Большая часть видимого overfitting — over-confidence, и её укрощает любое из пяти средств, а верных ответов заметно прибавляет только dropout. Модель эпохи 100 лучше модели эпохи 2: она выучила редкие темы и заплатила уверенностью, которую снимает один множитель после обучения — так работает temperature scaling, где логиты делят на температуру \(T = 1/s\), подобранную на validation. Следить при early stopping надо за тем, по чему модель будут судить: здесь за macro F1, за loss — когда важны сами вероятности.

Loss меряет и правильность, и уверенность, accuracy и F1 — только правильность: когда они спорят, сначала проверь уверенность.

В формате экзамена

In fit, the checkpoint of the best epoch is taken like this:

if val_score > best_score:
    best_score, wait = val_score, 0
    best_state = copy.deepcopy(model.state_dict())

What happens if the last line is replaced by best_state = model.state_dict()? Does the code raise an error?

Show model answer

model.state_dict() returns a dictionary whose values reference the live parameter tensors of the model. optimizer.step() updates these tensors in place, so without a copy best_state always equals the current weights. At the end, model.load_state_dict(best_state) loads the weights of the last epoch: early stopping silently returns the final model instead of the best one. No error is raised, because names and shapes match. copy.deepcopy stores an independent snapshot of the tensors at the record epoch.

Проверяют, что state_dict — ссылки, а не копия. Ответ «упадёт с ошибкой» неверен: всё работает и молча возвращает не ту модель — это и надо сказать.

The first line of train_one_epoch, model.train(), is deleted; evaluate still begins with model.eval(). What changes in the baseline run, and what in the run with dropout?

Show model answer

A new module starts in training mode, so epoch 1 trains normally. After the first call to evaluate the network stays in evaluation mode for the rest of the run: from epoch 2 on the nn.Dropout layers are identities, and the dropout run silently becomes a run without dropout. The baseline has neither dropout nor batch normalisation, so it is not affected. No error is raised; only the results change.

Важно сказать, что ломается только поведение, зависящее от режима (Dropout, BatchNorm), и что ошибки не будет. Частая неточность — «без train() не считаются градиенты»: градиенты выключает no_grad(), а не eval().

Training uses Adam and a hand-written L2 penalty with l2_lambda = 1e-4:

penalty += l2_lambda * sum(p.pow(2).sum() for p in model.parameters())

(a) Which of these two optimisers, used without the penalty, gives the same updates?

torch.optim.Adam(params, lr=1e-3, weight_decay=2e-4)
torch.optim.AdamW(params, lr=1e-3, weight_decay=2e-4)

(b) A weight \(w\) receives no gradient from the data. Write its update for Adam with this penalty and for AdamW with weight decay \(\lambda\). What happens to \(w\) in each case?

Show model answer

(a) Adam(..., weight_decay=2e-4). It adds \(2 \cdot 10^{-4}\, w\), the gradient of \(10^{-4} w^2\), to the gradient before the moment estimates, exactly as the hand-written penalty does (coupled L2). AdamW decouples the decay: a different method.

(b) Adam with the penalty: \(g = 2\lambda w\), and \(m\), \(v\) are built from \(g\):

\[ w \leftarrow w - \eta\,\frac{\hat m}{\sqrt{\hat v} + \varepsilon} \]

Since \(\hat m / \sqrt{\hat v} \approx g / |g| = \sign(w)\), the weight moves towards zero by about \(\eta\) per step, whatever \(\lambda\) is: with \(\eta = 10^{-3}\) a weight of 0.02 falls below \(10^{-3}\) in about 20 steps, then overshoots zero and oscillates around it with a shrinking amplitude. AdamW: the data gradient is zero, so \(m = v = 0\) and

\[ w \leftarrow (1 - \eta\lambda)\,w \]

a geometric decay by the same fraction \(\eta\lambda\) per step for every weight. With plain gradient descent both forms give \(w \leftarrow (1 - 2\eta\lambda)\,w - \eta\, \partial L / \partial w\), up to a factor 2 in \(\lambda\): they differ only because Adam normalises the gradient.

Главное — сказать, что Adam делит градиент штрафа на его собственный масштаб. Без последней фразы ответ неполон: равенство L2 и weight decay верно только для обычного градиентного спуска.

The best model of the lab has dropout layers. It is saved and reloaded:

torch.save(best_model.state_dict(), path)
loaded_model = make_model()
loaded_model.load_state_dict(torch.load(path, map_location=device))

The last line raises a RuntimeError about missing and unexpected keys. Why, if nn.Dropout has no parameters? How do you fix it, and what must you call before using the model for predictions?

Show model answer

A state_dict stores tensors by name, and the names are the positions of the modules in the nn.Sequential. With dropout the modules are Linear, ReLU, Dropout, Linear, …, so the linear layers are net.0, net.3, net.6, net.9; make_model() without dropout puts them at net.0, net.2, net.4, net.6. Keys such as net.2.weight are missing, and net.3.weight, net.9.weight are unexpected; net.6.weight exists in both, but with a different shape (512 × 512 in the file, 46 × 512 in the model). Fix: rebuild the same architecture, make_model(dropout_rate) with the rate of the saved model, then load. Before predicting call loaded_model.eval(): otherwise dropout stays active, each forward pass samples a different thinned network and the probabilities change from call to call. torch.no_grad() saves memory and time but does not change the numbers.

Проверяют, что файл весов не хранит архитектуру: её восстанавливает код. Хорошо отличить eval() (меняет поведение слоёв) от no_grad() (выключает только запись графа).

A data set has 46 classes, and the largest class holds 35.38 % of the samples. A classifier always predicts this class. What is its macro-averaged F1 score? (Classes that are never predicted count with F1 = 0.)

Show model answer

For the largest class precision is 0.3538 (every prediction is this class) and recall is 1:

\[ F_1 = \frac{2 \cdot 0.3538 \cdot 1}{0.3538 + 1} = 0.523 \]

The other 45 classes have no true positives, so their F1 is 0. Macro F1 = 0.523 / 46 = 0.0114. For comparison, accuracy is 0.354 and weighted F1 is 0.3538 · 0.523 = 0.185: only the macro average exposes the classifier.

Частые ошибки — дать в ответ F1 крупного класса (0.523) или среднее с весами (0.185). Здесь всё решают 45 нулей.

While a classifier trains, its validation cross-entropy is lowest at epoch 2 and more than triples by epoch 100, while validation accuracy stays almost flat and validation macro F1 doubles. Explain how this is possible. Which quantity should early stopping monitor here, and why?

Show model answer

Cross-entropy depends on the probability given to the true class; accuracy and F1 depend only on the arg max. After epoch 2 the network keeps learning the rare classes: macro F1 grows, while accuracy hardly moves because these classes have few samples. At the same time the weights, and with them the logits, keep growing; the softmax saturates and many of the remaining mistakes are made with probabilities close to 1, each costing a large \(-\ln p\). The loss rises from over-confidence, not from worse decisions: scaling all logits by one factor chosen on validation lowers it a lot without changing a single prediction.

Early stopping should monitor the quantity the model is judged on, here validation macro F1, and restore the best checkpoint; monitoring the loss would return the epoch-2 model. The loss is the right monitor when calibrated probabilities matter.

Проверяют разницу между правильностью и уверенностью. Хороший ответ называет механизм (рост логитов, насыщение softmax) и делает вывод о том, за чем следить.

Проверь себя

Модель на любую статью отвечает earn — 35 % данных. Что верно?

  • Accuracy около 0.35 Угаданы все статьи earn, а это 35 % всех.
  • Macro F1 около 0.01 F1 темы earn 0.52, у остальных 45 тем ноль; 0.52 / 46 ≈ 0.011.
  • Weighted F1 равен accuracy Weighted F1 = 0.354 · 0.523 = 0.185 — F1 одной темы с весом её доли.
  • Темы, которые модель ни разу не называет, в macro F1 не входят Входят: верных ответов у них нет, их F1 = 0, и 45 нулей тянут среднее вниз. zero_division на F1 здесь не влияет.

В fit строку заменили на best_state = model.state_dict(), без deepcopy. Какие веса будут у модели после early stopping с patience=20?

  • Веса лучшей эпохи, как и раньше state_dict() хранит ссылки на тензоры модели; step() меняет их на месте, и «лучшее состояние» меняется вместе с моделью.
  • Веса последней эпохи Откат загружает словарь, который всё время совпадал с текущими весами. Ошибки при этом нет.
  • Ошибка при load_state_dict Имена и формы совпадают, загрузка проходит молча — в этом и опасность.
  • Начальные веса сети Начальные веса нигде не сохранялись; словарь смотрит на текущие.

load_state_dict падает: missing key net.2.weight, unexpected key net.3.weight. Что произошло?

  • Файл весов повреждён Повреждённый файл не прочитался бы вовсе; здесь ключи читаются, но не те.
  • Веса сети с dropout загружают в сеть без dropout Dropout занимает места в nn.Sequential, и Linear стоят на позициях 0, 3, 6, 9, а не 0, 2, 4, 6.
  • Забыли map_location map_location меняет устройство тензоров, а не их имена.
  • Модель не переключили в eval() Режим train или eval на имена ключей не влияет, загрузка от него не зависит.

Все логиты baseline умножили на s = 0.19. Что изменилось на validation?

  • Validation loss Он упал с 3.42 до 1.31, уверенные ошибки стали дешевле.
  • Предсказанные темы Argmax не меняется от умножения на положительное число.
  • Macro F1 Он зависит только от ответов — 0.530, как и был.
  • Вероятность, которую сеть даёт своей лучшей теме Softmax стал мягче, и максимум вероятности уменьшился.

Градиент данных по весу 0.02 всё время равен нулю, \(\eta = 10^{-3}\). Что с ним будет за 2 460 шагов?

  • С Adam + L2 (\(\lambda = 10^{-4}\)) он умножается на \(1 - 2\eta\lambda\) за шаг и почти не меняется Так было бы у SGD. Adam делит градиент штрафа на его же масштаб, и шаг выходит около η.
  • С Adam + L2 он падает ниже \(10^{-3}\) за пару десятков шагов, а с AdamW (weight decay 0.1) теряет 0.01 % за шаг У Adam + L2 меньше 10⁻³ за 23 шага и меньше 10⁻³⁸ к шагу 1 538; у AdamW остаётся 0.02 · 0.9999²⁴⁶⁰ ≈ 0.0156.
  • С AdamW он тоже исчезает: усадку нормирует Adam В AdamW усадка (1 − ηλ) применяется к весу напрямую, мимо нормировки.
  • Ни с одним оптимизатором он не меняется: градиент же ноль Нулевой здесь только градиент данных; штраф и weight decay действуют на вес и без него.

Победитель по validation (macro F1 0.616) показал на test 0.561. Главная причина?

  • Статьи test сложнее Разбиение случайное и стратифицированное, в среднем test не сложнее validation; разницу объясняет то, как выбирали.
  • Validation выбирал эпоху и победителя, а максимум шести шумных оценок завышен Это winner's curse: честна только оценка на нетронутом test.
  • Модель переобучилась на test На test не обучали и по нему не выбирали: на него посмотрели один раз.
  • На test забыли выключить dropout predict вызывает model.eval(), dropout выключен.

Унести с собой

  • При перекосе 248 : 1 accuracy молчит: «всегда earn» даёт 0.354. Macro F1, среднее F1 по темам, даёт ему 0.011 — поэтому он служит метрикой и для early stopping, и для выбора модели.
  • Честное сравнение: make_model заново ставит seed — те же начальные веса и те же батчи, и прогоны различаются одной строкой.
  • Цикл: train(), zero_grad(), (loss + penalty).backward(), step(); проверка — eval() и no_grad(); early stopping — рекорд, deepcopy, wait >= patience, load_state_dict.
  • Validation loss и macro F1 спорят из-за over-confidence: растущие логиты удорожают ошибки, не меняя ответов. Early stopping по loss вернул бы эпоху 2 с F1 0.256.
  • Adam + L2 — не AdamW: в Adam градиент штрафа нормируется, и веса, которые данные не защищают, падают ниже \(10^{-38}\); AdamW снимает с каждого веса \(\eta\lambda\) = 0.01 % за шаг.
  • Validation выбирал дважды, поэтому 0.616 на test стало 0.561; разница между средствами, кроме dropout, — внутри шума одного разбиения.
  • Сохраняют state_dict, загружают в ту же архитектуру, с теми же слоями dropout, и перед ответами вызывают eval().
