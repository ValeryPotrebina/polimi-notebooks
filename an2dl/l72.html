Нормировать, чтобы учиться

После этого урока ты выберешь предобработку для CNN, посчитаешь параметры и статистики BatchNorm2d, свернёшь её в свёртку на тесте и переделаешь классификатор под несколько меток сразу.

Берёшь ResNet, обученную на ImageNet, и замораживаешь её целиком: backbone.requires_grad_(False). Ни один градиент её больше не тронет. Сверху ставишь новую голову, включаешь model.train() и одну эпоху учишь только голову. Потом сравниваешь числа внутри замороженной части с теми, что были до эпохи. Часть из них изменилась.

Какие числа сдвинулись без единого градиента, и почему при fine-tuning замороженную часть принято держать в другом режиме? Ответ — в третьем разделе. По дороге выяснится, какие числа сеть ждёт на входе, а в конце — что делать, если на снимке и собака, и кошка.

Где у данных начало координат

Представь два признака: один меняется от 0 до 1, другой от 0 до 1000. Шаг градиентного спуска с одним learning rate для второго веса огромен, для первого ничтожен. Поверхность ошибки — длинная узкая долина, и спуск скачет поперёк неё (урок 13). Если же все входы положительны, градиенты всех весов одного нейрона получают один знак, и веса движутся зигзагом. Обе беды лечит одно и то же: сдвинуть данные к нулю и выровнять разбросы (это объяснение из CS231n, на слайдах его нет).

Поэтому normalization полезна оптимизаторам на градиентах: она приводит данные "around the origin" и к похожим диапазонам, а на предобработанных данных модель учится легче и меньше чувствительна к возмущениям параметров (слайд 3 лекции 10).

Предобработок четыре, и каждая следующая делает больше предыдущей (слайды 4–5 лекции 10):

  • zero-centering — вычесть из каждого признака его среднее: X -= np.mean(X, axis=0);
  • normalization — после этого поделить каждый признак на его стандартное отклонение: X /= np.std(X, axis=0);
  • decorrelation — повернуть центрированное облако на главные оси PCA, чтобы матрица ковариации стала диагональной ("diagonal covariance matrix");
  • whitening — после поворота ещё поделить каждое главное направление на его разброс: "covariance = identity".

Последние две — PCA-based preprocessing, и делают их после центрирования. Первые две уже встречались в уроке 26, на картинке из лекции 3.

Что делают с картинками

Для CNN отбеливание почти не используют: "PCA Whitening/Preprocessing is not common in CNN training". Обычно делают две вещи: центрируют данные и нормируют каждый пиксель ("zero-center the data, normalize every pixel", слайд 6 лекции 10). Какими числами пиксель сдвигают и делят, бывает по-разному: три варианта на примере ImageNet, картинки [224, 224, 3], различаются тем, сколько чисел хранит каждый.

Последний вариант — тот, что сегодня стоит перед предобученными сетями torchvision. Для канала \(j\) среднее \(\mu_j\) и стандартное отклонение \(\sigma_j\) считают по всем обучающим картинкам и всем их пикселям, а потом каждый пиксель канала нормируют этими двумя числами:

\[ I'(r,c,j) = \frac{I(r,c,j) - \mu_j}{\sigma_j} \]

Статистика — часть модели

Главное правило раздела: "Normalization statistics are parameters of your ML model" (слайд 7 лекции 10). Из него следуют три вещи.

  • Статистику считают только по training set и потом теми же числами нормируют validation и test. Среднее test set для test set — это подсмотренный ответ.
  • "Do not normalize first and then split": если нормировать до разбиения, в среднее попадут валидационные и тестовые картинки, и оценка качества выйдет оптимистичной (утечка, как в уроке 18).
  • С предобученной моделью надо "import (and use!)" её собственную функцию предобработки.

Средние и разбросы предобработки — такие же параметры модели, как веса: их оценивают один раз на обучающих данных и больше не трогают.

Третий пункт — про чужие очки. Предобученная ResNet привыкла смотреть на пиксели ImageNet, нормированные числами ImageNet: на картинках, приведённых к [0, 1], это mean 0.485 / 0.456 / 0.406 и std 0.229 / 0.224 / 0.225 для каналов R, G, B. Её первые фильтры настроены на входы именно с такой нормировкой. Если пересчитать «правильные» средние по своему датасету, сеть увидит сдвинутые и растянутые входы.

Поэтому с предобученной сетью берут её статистику. В torchvision эти очки лежат прямо в весах: weights.transforms() меняет размер, вырезает центр, переводит пиксели в [0, 1] и нормирует числами ImageNet (урок 71). Свою статистику считают только для сети, которую учат с нуля: по обучающей части, а нормируют ею все три части (этого кода на слайдах нет):

import torch
from torchvision import transforms

# a network trained from scratch: statistics
# of the TRAINING split only, 3 + 3 numbers
x = torch.stack([img for img, _ in train_set])  # (N, 3, H, W)
mean = x.mean(dim=(0, 2, 3))
std = x.std(dim=(0, 2, 3))

# the same numbers for train, validation and test
normalise = transforms.Normalize(mean.tolist(), std.tolist())

Одна кривая на канал

Предобработка нормирует вход сети. Но второй слой получает выходы первого, и их распределение гуляет с каждым шагом обучения. В уроке 26 это лечила batch normalization (BN): каждый нейрон «оценивается по кривой» — его значения нормируются средним и разбросом по текущему mini-batch. Там у каждого нейрона была своя кривая. Чем в свёрточном слое заменить «нейрон»?

Выход свёрточного слоя на mini-batch — тензор (N, C, H, W): \(N\) картинок, у каждой \(C\) карт размера \(H \times W\). Карта \(j\) — это один фильтр, приложенный ко всем позициям, с одними и теми же весами (урок 59). Значит, все позиции канала — один и тот же «нейрон», и статистика у них должна быть общей. Это как оценка по кривой в школе с несколькими предметами: математику, физику и литературу нормируют отдельно, но каждую — по всем ученикам и всем вопросам сразу. Предмет — канал, ученики — картинки mini-batch, вопросы — позиции \((r, c)\).

Слайд записывает z-score normalization так (слайд 9 лекции 10):

\[ x_i' = \frac{x_i - E[x_i]}{\sqrt{\mathrm{var}[x_i]}} \]

и подчёркивает: \(E[x_i]\) и \(\sqrt{\mathrm{var}[x_i]}\) "are computed from each batch and separately for each channel!" Расписанная по индексам, BN считает для канала \(j\) среднее и дисперсию по \(N \cdot H \cdot W\) значениям:

\[ \mu_j = \frac{1}{NHW}\sum_{n,r,c} x_n(r,c,j) \] \[ \sigma_j^2 = \frac{1}{NHW}\sum_{n,r,c} \bigl(x_n(r,c,j) - \mu_j\bigr)^2 \] \[ y_n(r,c,j) = \gamma_j\,\frac{x_n(r,c,j) - \mu_j}{\sqrt{\sigma_j^2 + \epsilon}} + \beta_j \]
\(x_n(r,c,j)\)
значение карты \(j\) картинки \(n\) в позиции \((r, c)\): вход слоя BN, то есть выход свёртки
\(\mu_j,\ \sigma_j^2\)
среднее и дисперсия канала \(j\) по mini-batch (на слайдах \(E[x_i]\) и \(\mathrm{var}[x_i]\))
\(\gamma_j,\ \beta_j\)
scale и shift канала \(j\), обучаемые
\(\epsilon\)
маленькая константа против деления на ноль, в PyTorch \(10^{-5}\)

На рисунке слайда тензор нарисован кубиком. У Batch Norm синий слой занимает один канал C и тянется через всю ось N и все H, W; три соседних кубика — другие нормализации, они берут другие куски того же тензора. Виджет ниже разворачивает этот кубик в таблицу карт.

Кто делит одно среднее

Тензор (N, C, H, W) = (3, 4, 3, 3): столбец — одна картинка mini-batch, строка — один канал, в каждой клетке значение выхода свёртки. Щёлкни по клетке (или выбери картинку и канал ползунками): жёлтым подсветятся все значения, которые нормируются тем же средним и той же дисперсией. LayerNorm, InstanceNorm и GroupNorm — для сравнения, их нет на слайдах.

  1. Режим BatchNorm2d. Сколько клеток загорится, если щёлкнуть по каналу 2 первой картинки? Предскажи формулой, потом щёлкни.
    Что должно получиться

    Вся строка канала 2: \(N \cdot H \cdot W = 3 \cdot 3 \cdot 3 = 27\) клеток, во всех картинках и на всех позициях. Пар \((\mu, \sigma^2)\) у слоя столько, сколько каналов, — четыре.

  2. Пощёлкай по разным строкам и сравни \(\mu\) каналов 1 и 4. Почему одна общая статистика на весь тензор была бы плохой идеей?
    Что должно получиться

    У канала 1 \(\mu = 1.89\), у канала 4 — \(6.74\). Каналы — разные фильтры с разными шкалами. Общее среднее сдвинуло бы канал 1 в минус, а канал 4 в плюс, и ничего бы не выровняло.

  3. Переключи на LayerNorm, потом на InstanceNorm. Какая из трёх нормализаций зависит от того, какие ещё картинки попали в mini-batch?
    Что должно получиться

    Только BatchNorm: её строка проходит через все картинки. LayerNorm горит столбцом (одна картинка, все каналы, 36 значений), InstanceNorm — одной картой (9 значений). Обе считаются внутри одной картинки, поэтому им всё равно, кто соседи, и они одинаково работают на обучении и на тесте.

Под кубиками на слайде стоит вопрос: "There are no trainable parameters here: Can we get more flexibility than z-score normalization?" Ответ — тот же, что в уроке 26: после нормировки слой растягивает и сдвигает результат обучаемыми числами (слайд 10 лекции 10). На слайде это \(y_{i,j} = \gamma_j x_i' + \beta_j\), где \(j\) — канал: "We have \(\gamma\) and \(\beta\) for each channel of the input activation". Сеть сама решает, какое среднее (\(\beta_j\)) и какой разброс (\(\gamma_j\)) нужны каналу, и может даже вернуть всё как было, выучив \(\gamma_j = \sigma_j\), \(\beta_j = \mu_j\).

Среднее и разброс по batch, наоборот, "non-trainable parameters": их не учат градиентом, их считают. На слайде 10 лекции 10 корень \(\sqrt{\mathrm{var}[x_i]}\) назван "variance", но это стандартное отклонение, а слой хранит дисперсию \(\sigma_j^2\); вопрос экзамена может быть составлен словами слайда, так что знай и напечатанное название, и верное.

Слайд 11 лекции 10 повторяет алгоритм Ioffe и Szegedy — те же четыре шага с \(\epsilon\) в знаменателе, что разобраны на числах в уроке 26. Для свёрточного слоя меняется только одно: «mini-batch» одного канала состоит не из \(N\), а из \(N \cdot H \cdot W\) значений.

Обучение, тест и замороженная сеть

На обучении \(\mu_j\) и \(\sigma_j^2\) берутся из текущего mini-batch. На тесте так нельзя: предсказание для одной картинки зависело бы от того, какие картинки оказались с ней в одной пачке, а картинка, пришедшая одна, нормировалась бы только по собственным картам. Поэтому "after training, these are replaced by (running) averages computed on training samples" (слайд 10 лекции 10). Слой копит их по ходу обучения, после каждого mini-batch:

\[ \mu_{\mathrm{run}} \leftarrow (1 - 0.1)\,\mu_{\mathrm{run}} + 0.1\,\mu_j \]

и так же для дисперсии. Число 0.1 — параметр momentum слоя в PyTorch (слайд 13 лекции 10), в уроке 26 он обозначен \(\alpha\). С оптимизатором с моментом он ничего общего не имеет.

Отдельное предупреждение: "This layer behaves differently during training and inference, like dropout" (слайд 15 лекции 10). В PyTorch режим переключают для всей модели сразу. model.train(): BN нормирует статистикой batch и обновляет running averages. model.eval(): BN нормирует накопленными числами и ничего не обновляет. Без eval() перед проверкой ответ на одну картинку зависит от соседей, а архив статистики дописывается тестовыми данными.

Ответ на задачку

Вот что сдвинулось в замороженной ResNet: running_mean и running_var каждого слоя BatchNorm2d (и счётчик num_batches_tracked). Это не параметры, а буферы: градиент их не трогает, и requires_grad_(False) к ним не относится. Их обновляет сам прямой проход в режиме train().

За эпоху на новом датасете статистика замороженных слоёв переехала на новые данные, а замороженные веса после них ждут старую, с ImageNet. С маленькими mini-batch она к тому же шумит. Поэтому при fine-tuning (урок 71) замороженную часть держат в режиме eval(), даже когда остальная модель учится:

model.train()      # the head learns
backbone.eval()    # frozen BN layers keep
                   # the ImageNet statistics

На тесте BN — просто прямая

"During testing batch normalization becomes a linear operator! Can be fused with the previous fully-connected or conv layer" (слайд 12 лекции 10). На тесте \(\mu_{\mathrm{run}}\), \(\sigma^2_{\mathrm{run}}\), \(\gamma_j\), \(\beta_j\) — четыре константы канала, и слой превращается в \(y = s\,x + \text{const}\). А такую операцию можно спрятать внутрь свёртки, которая стоит перед ним. Пусть фильтр \(j\) свёртки с весами \(\vb{w}^j\) и смещением \(b^j\) даёт канал \(j\): \(x = (\vb{w}^j)\T \vb{p}_{r,c} + b^j\), где \(\vb{p}_{r,c}\) — развёрнутое в вектор окно входа (урок 58).

  1. На тесте слой BN канала \(j\) — формула с одними константами:

    \[ y = \gamma_j\,\frac{x - \mu_{\mathrm{run}}}{\sqrt{\sigma^2_{\mathrm{run}} + \epsilon}} + \beta_j \]

  2. Обозначим множитель \(s_j = \gamma_j / \sqrt{\sigma^2_{\mathrm{run}} + \epsilon}\) и раскроем скобки. Получилась прямая со сдвигом — строго говоря, аффинное, а не линейное отображение:

    \[ y = s_j\,x + (\beta_j - s_j\,\mu_{\mathrm{run}}) \]

  3. Подставим выход свёртки \(x = (\vb{w}^j)\T \vb{p}_{r,c} + b^j\):

    \[ y = s_j (\vb{w}^j)\T \vb{p}_{r,c} + s_j b^j + \beta_j - s_j\,\mu_{\mathrm{run}} \]

  4. Сгруппируем. Это снова свёртка, только с другими весами и смещением:

    \[ \vb{w}'^j = s_j\, \vb{w}^j \] \[ b'^j = s_j\,(b^j - \mu_{\mathrm{run}}) + \beta_j \]

  5. На числах урока 26 (\(\mu_{\mathrm{run}} = 4\), \(\sigma^2_{\mathrm{run}} = 5\), \(\gamma = 2\), \(\beta = 1\), \(\epsilon \approx 0\)) и свёртке 1 × 1 с весом 0.5 и смещением 1:

    \[ s = 2/\sqrt{5} = 0.894 \] \[ w' = 0.894 \cdot 0.5 = 0.447 \] \[ b' = 0.894 \cdot (1 - 4) + 1 = -1.683 \]

Отсюда пункт "Zero overhead at test-time: can be fused with conv!" из списка достоинств (слайд 15 лекции 10). Сворачивать можно, когда BN стоит сразу за свёрткой или полносвязным слоем, без нелинейности между ними — как в стандартном блоке ниже.

BatchNorm2d в коде: параметры и место

В PyTorch слой для тензоров (N, C, H, W) — nn.BatchNorm2d (слайд 13 лекции 10):

torch.nn.BatchNorm2d(num_features, eps=1e-05, momentum=0.1,
                     affine=True, device=None, dtype=None)

# With Learnable Parameters
m = nn.BatchNorm2d(100)
# Without Learnable Parameters
m = nn.BatchNorm2d(100, affine=False)

num_features — это \(C\), число каналов входа. eps — \(\epsilon\) в знаменателе. momentum — вес свежего batch в running averages; None даёт простое среднее по всем batch ("cumulative moving average"). affine=False убирает \(\gamma\) и \(\beta\): остаётся чистый z-score. В нынешней сигнатуре есть ещё track_running_stats=True; слайд его не печатает.

Сколько чисел хранит слой

На каждый канал \(\gamma\) и \(\beta\) — "Trainable Parameters: 2 × C", плюс running mean и running variance — "Non-Trainable Parameters: 2 × C", итого "Total Parameters: 4 × C" (слайд 14 лекции 10). Для входа (N, 64, H, W): 128 обучаемых + 128 отслеживаемых = 256. От \(N\), \(H\) и \(W\) счёт не зависит. В коде число будет другим: sum(p.numel() for p in bn.parameters()) для BatchNorm2d(64) вернёт 128, потому что PyTorch хранит running statistics как буферы, а не параметры. На экзамене отвечай, как на слайде: \(2C\) обучаемых и \(2C\) необучаемых.

Стандартный блок

Смещение свёртки перед BN бесполезно: BN вычитает среднее канала, а вместе с ним и любую добавленную к каналу константу, \(\mathrm{BN}(x + b) = \mathrm{BN}(x)\) (урок 26). Его работу делает \(\beta_j\). Поэтому свёртку перед BN создают с bias=False:

block = nn.Sequential(
    # (3*3*64)*128 = 73 728 weights, no bias
    nn.Conv2d(64, 128, kernel_size=3, padding=1, bias=False),
    # 2*128 = 256 trainable, 256 running statistics
    nn.BatchNorm2d(128),
    nn.ReLU(),
)

Со смещением у свёртки было бы на 128 параметров больше, \(73\,856\), и все 128 лишние. В современных CNN BN стоит после практически каждой свёртки, блоком conv → BN → ReLU: так устроены ResNet и остальные сети torchvision с BN. Фраза слайда 12 лекции 10, что BN "typically" ставят между FC-слоями и лишь "sometimes" между свёрточными, устарела: уже слайд 13 лекции 10 посвящён BatchNorm2d, версии для свёрток (экзамен может взять формулировку слайда, так что знай и её, и нынешнюю практику).

Почему BN стоит почти везде — список достоинств со слайда 15 лекции 10 (механизмы разобраны в уроке 26):

  • "Makes deep networks much easier to train!", "Improves gradient flow";
  • "Allows higher learning rates, faster convergence";
  • "Networks become more robust to initialization";
  • "Acts as regularization during training": выход каждой картинки зависит от случайных соседей по batch;
  • "Zero overhead at test-time: can be fused with conv!"

И одно предупреждение: разное поведение на обучении и на тесте — то самое, на котором попалась замороженная ResNet.

Радио или галочки

На фотографии со слайда собака разинула пасть над головой рыжей кошки (слайд 17 лекции 10). Какой класс должен вернуть классификатор? Правильный ответ — оба. Но все классификаторы курса до сих пор возвращали ровно одну метку: softmax на выходе (урок 11) делает из оценок вероятности, которые в сумме дают 1, и ответ — самый вероятный класс. Хочется классификатор, который возвращает "a varying number of labels" — переменное число меток, в том числе ни одной.

Это разница между двумя типами вопросов в анкете. Softmax — радиокнопки: «какое одно животное на фото?» — выбор одной кнопки снимает остальные. Multi-label classification — галочки: «отметь всех, кого видишь», любое число, хоть ни одного. Рецепт — три пункта (слайд 18 лекции 10):

  • "Replacing the softmax activation in the output layer with a sigmoid activation in each output neuron";
  • \(i\)-й выход предсказывает вероятность \(p_i \in [0, 1]\) принадлежности к классу \(i\) "in a non-exclusive manner" — независимо от остальных;
  • "The model must be trained with the binary cross-entropy loss function".

"These probabilities do not sum to 1": фото может принадлежать нескольким классам сразу, и картинку со слайда, скорее всего, отнесут и к «dog», и к «cat». Цель обучения — не one-hot, а multi-hot вектор \(t\): единицы у всех присутствующих классов. Каждый выход — свой вопрос «да / нет», то есть своя монетка, как в уроке 11, и ошибка — сумма binary cross-entropy по \(L\) выходам (формулы на слайде нет):

\[ \begin{aligned} E = -\sum_{i=1}^{L} \bigl[ & t_i \ln p_i \\ & + (1 - t_i) \ln (1 - p_i) \bigr] \end{aligned} \]

Метку \(i\) ставят, если \(p_i \gt \tau\), обычно \(\tau = 0.5\); если ни одна \(p_i\) не прошла порог, ответ — пустое множество. Для логитов (2, 1, −3) кошки, собаки и машины с целью (1, 1, 0) ошибка равна \(0.127 + 0.313 + 0.049 = 0.489\).

Радио или галочки

Три логита — выходы последнего слоя до активации — идут в две головы сразу. Сверху softmax: полоски в сумме дают 1, выбирается одна кнопка. Снизу независимые сигмоиды: галочка ставится каждому классу, у которого \(p_i\) выше порога \(\tau\).

  1. Логиты (2, 1, −3), как стоят. Что ответит каждая голова?
    Что должно получиться

    Softmax: кошка, 0.73 (собака 0.27, машина 0.00). Сигмоиды: кошка 0.88 и собака 0.73 — обе галочки; машина 0.05 — нет. Сумма сигмоид 1.66.

  2. Подними логит собаки с 1 до 3. Что случится с вероятностью кошки в каждой голове?
    Что должно получиться

    В softmax кошка упала с 0.73 до 0.27: классы делят одну единицу, и рост собаки отнимает у кошки. Сигмоида кошки осталась 0.88: её никто не трогал. Это и значит "non-exclusive".

  3. На фото нет ни одного из трёх классов: поставь логиты (−3, −2, −4). Что ответят головы?
    Что должно получиться

    Softmax всё равно выбирает: собака, 0.67 — сказать «никого нет» он не может. Все сигмоиды ниже 0.5 (0.05, 0.12, 0.02): ни одной галочки, пустой ответ.

В PyTorch сигмоиду в модель обычно не ставят: последний слой выдаёт логиты, а nn.BCEWithLogitsLoss применяет сигмоиду и binary cross-entropy вместе, так численно устойчивее. Цель — float-тензор из нулей и единиц той же формы, что выход. nn.CrossEntropyLoss сюда не годится: внутри него softmax, и классы снова начнут делить одну единицу (этого кода на слайдах нет).

head = nn.Linear(d, L)            # no sigmoid in the model
loss_fn = nn.BCEWithLogitsLoss()
logits = head(features)           # shape (N, L)
# targets: float multi-hot, shape (N, L)
loss = loss_fn(logits, targets)

# inference: a threshold for every class
labels = torch.sigmoid(logits) > 0.5

Порог не обязан быть общим: его можно подобрать для каждого класса отдельно на validation set. Та же фотография с собакой и кошкой вернётся в уроке 79 с другим вопросом: сеть сказала «оба» — а где на картинке каждый?

В формате экзамена

A convolutional layer outputs a tensor of shape \((N, C, H, W) = (16, 64, 32, 32)\), followed by nn.BatchNorm2d(64). During training, over how many values is the mean of each channel computed?

Show model answer

BatchNorm2d computes one mean and one variance per channel, over the batch and all spatial positions: \(N \cdot H \cdot W = 16 \cdot 32 \cdot 32 = 16\,384\) values. There are 64 such means, one per channel.

Проверяют «по каналу, по N, H, W». Типичные неверные ответы: 16 (как будто нормируют только по batch, по одному значению на позицию) и \(64 \cdot 32 \cdot 32\) (так считает LayerNorm).

Count the trainable parameters of nn.Conv2d(64, 128, kernel_size=3, padding=1, bias=False) followed by nn.BatchNorm2d(128). Why is the convolution created without bias?

Show model answer

Convolution: \((3 \cdot 3 \cdot 64) \cdot 128 = 73\,728\). BatchNorm2d: \(\gamma\) and \(\beta\) per channel, \(2 \cdot 128 = 256\). Total trainable: \(73\,984\). BN also stores \(2 \cdot 128 = 256\) non-trainable statistics (running mean and running variance), \(4C = 512\) numbers in total. The bias is redundant: BN subtracts the channel mean, which cancels any constant added to the channel, and \(\beta\) takes its role.

Два места для ошибки: забыть, что \(\gamma, \beta\) — по каналу (а не по позиции), и посчитать running statistics обучаемыми. Если спрашивают «all parameters» по слайду 14 лекции 10, ответ BN — \(4C\).

At test time a batch-normalization channel has running mean 4, running variance 5, \(\gamma = 2\), \(\beta = 1\), and \(\epsilon \approx 0\). It follows a \(1 \times 1\) convolution whose weight is 0.5 and bias is 1 for that channel. Fold BN into the convolution: what is the bias of the fused convolution (three decimals)?

Show model answer

At test time BN is the affine map \(y = s\,x + (\beta - s\,\mu)\) with \(s = \gamma / \sqrt{\sigma^2 + \epsilon} = 2 / \sqrt{5} = 0.894\). Substituting \(x = w u + b\): \(w' = s\,w = 0.447\) and

\[ \begin{aligned} b' &= s\,(b - \mu) + \beta \\ &= 0.894 \cdot (1 - 4) + 1 = -1.683 \end{aligned} \]

Проверка на одном входе: при \(u = 2\) обе версии дают \(-0.789\). Если вышло \(-2.578\), смещение свёртки забыто.

Why must the mean and standard deviation used to normalize the inputs be computed on the training set only? What changes when you fine-tune a network pretrained on ImageNet?

Show model answer

Normalization statistics are parameters of the model. Estimating them on validation or test data leaks information from those sets into training and makes the performance estimate optimistic; so we split first, compute the statistics on the training split and apply the same numbers to validation and test. A pretrained network was trained on inputs normalized with its own statistics (ImageNet: mean 0.485, 0.456, 0.406 and std 0.229, 0.224, 0.225 per channel), so we must use its preprocessing function, not statistics of our dataset.

Ключевые слова: "parameters of the model", "split first", "apply to validation and test", "use the pretrained model's preprocessing". Числа ImageNet называть не обязательно, но они показывают, что ты понимаешь, о чём речь.

Batch normalization behaves differently during training and inference. Explain the difference, what goes wrong if you forget model.eval(), and why BN adds no cost at test time.

Show model answer

During training BN normalizes each channel with the mean and variance of the current mini-batch (over N, H, W) and updates running averages of them (momentum 0.1 in PyTorch). At inference the running averages are used. Without model.eval() a prediction depends on the other images in the batch and the running statistics are overwritten by test data. At test time the mean, variance, \(\gamma\) and \(\beta\) are constants, so BN is an affine map per channel and can be fused into the preceding convolution: \(w' = s\,w\), \(b' = s\,(b - \mu) + \beta\), with \(s = \gamma / \sqrt{\sigma^2 + \epsilon}\).

Три части — три балла. Слово "affine" (на слайде "linear operator") плюс формула свёртки показывают, что фраза "can be fused" понята, а не заучена.

A CNN must return every object class present in an image, possibly none. Which modifications of a standard softmax classifier are needed? Select all that apply.

  • A sigmoid activation in each output neuron instead of the softmax Каждый выход отвечает на свой вопрос «да / нет», независимо от остальных.
  • Training with the binary cross-entropy loss on a multi-hot target Это прямо третий пункт слайда 18 лекции 10: каждый выход — монетка Бернулли.
  • A threshold applied to each output independently Метка ставится, если \(p_i \gt \tau\); если не прошёл ни один выход, ответ пустой.
  • Keeping the softmax and returning every class with probability above 0.5 Softmax даёт в сумме 1, поэтому выше 0.5 может оказаться не больше одного класса: кошку и собаку сразу он не вернёт.
  • Training with categorical cross-entropy on a one-hot target One-hot кодирует ровно одну метку, а categorical cross-entropy содержит softmax: классы опять конкурируют.
Show model answer

Replace the softmax with one sigmoid per output, so that each \(p_i \in [0, 1]\) is predicted in a non-exclusive way, train with binary cross-entropy on multi-hot targets, and assign label \(i\) when \(p_i\) exceeds a threshold. The outputs no longer sum to 1, and any number of labels, including none, can be returned.

Экзаменатор проверяет, что ты понимаешь, почему softmax не годится: классы делят одну единицу. Запомни фразу слайда "These probabilities do not sum to 1".

Проверь себя

После шага normalization у каждого признака среднее 0 и разброс 1. Что можно сказать о связи между признаками?

  • Её больше нет: признаки стали независимыми Деление на разброс меняет масштаб каждой оси отдельно и не трогает корреляцию: в виджете она так и осталась 0.90.
  • Она осталась прежней: корреляция не меняется от сдвига и масштаба Да. Убрать её может только поворот на главные оси — decorrelation.
  • Ковариация стала единичной матрицей Это whitening. После нормализации на диагонали единицы, но вне диагонали остаётся корреляция.

Выход свёртки имеет форму (8, 32, 14, 14), за ней BatchNorm2d. Сколько разных средних слой считает на одном шаге обучения?

  • 32 По одному на канал, каждое — по \(8 \cdot 14 \cdot 14 = 1568\) значениям.
  • 8 Это одно среднее на картинку — так считает LayerNorm.
  • \(8 \cdot 32 = 256\) По одному на карту каждой картинки — это InstanceNorm.
  • \(32 \cdot 14 \cdot 14 = 6272\) Так было бы, если бы каждая позиция была своим нейроном. Но позиции канала — один фильтр с общими весами, и статистика у них общая.

Среднее и разброс по каналам посчитали по всему датасету, а потом разбили его на train / validation / test. Что не так?

  • В статистику попали валидационные и тестовые картинки: утечка, оценка качества выйдет оптимистичной Да: статистика — параметр модели, и её, как веса, учат только на обучающих данных.
  • Ничего: средние по всему датасету точнее Точнее, но это знание о тесте, которого у модели в реальной работе не будет.
  • Нормализация до разбиения ломает метки классов Метки она не трогает; проблема в том, откуда взяты числа.

Что меняется в слое BatchNorm2d после model.eval()? Отметь всё верное.

  • Он нормирует running mean и running variance, а не статистикой batch Это и есть режим inference.
  • Он перестаёт обновлять running statistics Да: в eval() прямой проход их не трогает. Поэтому замороженный backbone держат в eval().
  • Ответ на картинку перестаёт зависеть от остальных картинок batch Все числа слоя теперь константы.
  • \(\gamma\) и \(\beta\) перестают получать градиент Нет: eval() меняет поведение слоя, а не requires_grad. Градиент по \(\gamma\), \(\beta\) по-прежнему считается, если сделать backward.

Зачем свёртку перед BN создают с bias=False?

  • BN вычитает среднее канала и вместе с ним любую константу; роль смещения играет \(\beta\) Верно: \(\mathrm{BN}(x + b) = \mathrm{BN}(x)\), так что 128 смещений свёртки на 128 каналов были бы лишними параметрами.
  • Со смещением BN нельзя свернуть в свёртку на тесте Можно: в формуле \(b' = s\,(b - \mu_{\mathrm{run}}) + \beta\) смещение просто входит в новое.
  • Со смещением обучение расходится Не расходится: смещение просто ничего не делает, его градиент равен нулю.

Multi-label классификатор выдал логиты (−1, −2, −3), порог 0.5. Сколько меток он вернёт?

  • Ни одной Все логиты отрицательны, значит все сигмоиды меньше 0.5 (0.27, 0.12, 0.05). Порог 0.5 — это логит 0.
  • Одну, первый класс Так ответил бы softmax: он выбирает всегда. Сигмоиды смотрят на каждый класс отдельно.
  • Все три Сигмоида отрицательного логита меньше 0.5.

Унести с собой

  • Лестница предобработки: zero-centering → normalization (разбросы равны, корреляция осталась) → decorrelation (PCA, ковариация диагональна) → whitening (ковариация единичная). CNN обходятся вычитанием среднего и нормировкой: средняя картинка (AlexNet, 150 528 чисел), средние каналов (VGG, 3), средние и разбросы каналов (ResNet, 3 + 3), \(I'(r,c,j) = (I(r,c,j) - \mu_j)/\sigma_j\).
  • "Normalization statistics are parameters of your ML model": считаются на training split после разбиения и применяются к validation и test; у предобученной сети — её предобработка (ImageNet: 0.485 / 0.456 / 0.406 и 0.229 / 0.224 / 0.225, weights.transforms()).
  • BatchNorm2d нормирует каждый канал по \(N \cdot H \cdot W\) значениям и применяет свои \(\gamma_j\), \(\beta_j\): \(y = \gamma_j (x - \mu_j)/\sqrt{\sigma_j^2 + \epsilon} + \beta_j\).
  • На обучении — статистика batch и обновление running averages (momentum=0.1), на тесте — только они: model.train() против model.eval(). Буферы BN обновляет прямой проход, поэтому requires_grad_(False) их не замораживает.
  • На тесте BN аффинна и сворачивается в предыдущую свёртку: \(s = \gamma/\sqrt{\sigma^2_{\mathrm{run}} + \epsilon}\), \(w' = s\,w\), \(b' = s\,(b - \mu_{\mathrm{run}}) + \beta\).
  • Параметры BatchNorm2d(C): \(2C\) обучаемых + \(2C\) running statistics = \(4C\) по слайду (parameters() в PyTorch покажет \(2C\)). Блок conv → BN → ReLU стоит после почти каждой свёртки, свёртка — с bias=False.
  • Multi-label: сигмоида на каждом выходе вместо softmax, binary cross-entropy на multi-hot цели (nn.BCEWithLogitsLoss), порог для каждого класса; вероятности не складываются в 1, меток может быть сколько угодно, в том числе ни одной.
