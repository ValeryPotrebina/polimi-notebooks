Four nodes, one block: directory walkthroughs and the exam exercise

After this lesson you will take any directory entry and any request, name the home, local and remote nodes, write the message sequence with its senders and receivers, and give the final states, sharer bits and owner — the 5-point directory exercise of the recent papers, solved in full.

The paper of 22 June 2026 gives one line, Directory N0 Block B0 | State: SHARED | Sharer Bits: 1001, one event, a Write Miss on B0 from N2, and eleven boxes to fill. Ten of them ask for a name or a state. The seventh asks for a reason: "Is(are) there any message(s) sent from the remote node(s) to the home node? Why?"

N0 and N3 hold copies of B0, and the home is about to destroy them. Should they send their data back first, as an owner in the same position must? Write down yes or no, and why. The lesson comes back to your answer once every scenario of the protocol has run.

One block, one home, three shapes

Take the machine of the three papers and of the notes (Fig. 42, p. 468): four nodes N0 … N3, each with a processor P, a cache C, a main memory MM and a directory D, on one interconnection network. The physical address space is statically partitioned among the nodes, so every block has exactly one home. The notes follow one block, B0, whose home is N0: B0 lives in MM0, and its directory entry lives in D0.

The papers write the entry on one line, and so does this lesson: Directory N0 Block B0 | State: Shared | Sharer Bits: 1001. The state is Uncached, Shared or Modified. The four sharer bits are read left to right as N0 N1 N2 N3, so 1001 means that C0 and C3 hold copies. In Modified exactly one bit is set, and it names the owner.

The three roles come from the same lesson. The home holds the block in its memory and keeps its entry; the local node issues the request; a remote node is one whose cache holds a copy, Shared or Modified. One node can play two roles: in the June 2026 entry N0 is the home and, because C0 holds a copy, also a remote.

Lesson 37 pictured the home as a librarian with a lending card for every book. Asked for a book, the librarian has only three ways to answer, and every scenario of this lesson is one of them (Fig. 1). If the copy on the shelf is good — nobody has the book, or readers hold only photocopies — the librarian lends from the shelf. If readers hold photocopies and someone wants to edit, the readers are told to shred them, and they bring nothing back: a photocopy holds nothing the shelf lacks. If one reader holds the edited master, the shelf copy is out of date, and the master must come back first.

The home answers from its own memory whenever memory is up to date (Uncached, Shared); only in Modified must it first fetch the block from the owner. A clean copy is told to invalidate and sends nothing back.

Two things in the entry make this possible. The state tells the home whether its memory can be trusted: yes in Uncached and Shared, no in Modified. The sharer bits tell it whom to contact, so nothing is ever broadcast: only the nodes the bits name receive a message.

Uncached and Shared: the memory answers

Run the notes' walkthrough on B0 (pp. 469–471). Start from Directory N0 Block B0 | Uncached | 0000: no cache holds B0, and MM0 has the only copy. N1 reads B0 and misses. N1 sends a Read Miss to N0; N0 answers with a Data Value Reply read from MM0 and sets N1's bit: Shared | 0100. Two messages, and memory is still up to date, because N1 holds a clean photocopy.

From the same Uncached entry, a Write Miss from N2 costs two messages too. There is nobody to invalidate, so the home replies at once and records N2 as the owner: Modified | 0010. N2 writes into its copy, and from that moment MM0 is stale.

The Shared cases are the ones the papers ask. Take Shared | 0100, where only C1 holds B0, and the two requests of the notes. The table uses the columns of the June 2025 paper.

In the Read Miss from N2, N1 is a remote node — its cache holds a copy — yet it receives nothing. In Shared, memory is up to date, so the home replies from MM0 by itself; asking N1 would only add a message.

"The data is read from one of the caches that already has it (see page 470 for more details)."

In Shared the data is read from the home's memory: memory is up to date, and no cache is involved.

Page 470, which the sentence cites, says the opposite: "Home sends data from memory". The protocol has no message that asks a clean sharer for data — a Fetch goes only to an owner in Modified — and the notes' own invariant 2 (p. 478) says that in Shared memory is up to date. In the June 2025 exercise the Data Value Reply of the first access comes from MM1.

The notes' walkthrough (p. 471) adds an "Ack" from N1 to the home. Real machines acknowledge invalidations, but the seven messages of the course have no Ack: at the exam, N1 sends nothing.

In the Write Miss from N2, N1 must lose its copy before N2 may write. The home sends N1 an Invalidate, then the Data Value Reply to N2. N1 invalidates and sends no data back: its copy was clean, identical to MM0, so there is nothing to save.

A write hit on a Shared block

The papers add a scenario the notes never walk: the local node already holds the block Shared and writes it. Take the second access of June 2025, Directory N1 Block B1 | Shared | 0110 and a Write Hit from N2. N2 already has the data, so it needs no block, only permission. It sends an Invalidate to the home N1, which invalidates every other sharer — here the copy in its own cache C1 — and makes N2 the owner: Modified | 0010. That is 1 + k messages for k other sharers, and no Data Value Reply. With k = 0 the request is still sent, because the home must learn that N2 now owns a dirty block.

"A write hit on Shared is just a write, so the local node sends a Write Miss." No: a Write Miss asks for the data and gets a Data Value Reply. A write hit on a Shared block sends an Invalidate request and gets no data. The June 2025 and July 2024 papers both test it.

Two quieter cases

When the local node is the home, only the route changes. In the first access of the July 2024 quiz (question 4), N1 reads B1 and N1 is B1's home: C1 asks D1, MM1 answers, and N1's bit is set. It is the same pair of messages, inside one node, and the entry goes from Shared | 1001 to Shared | 1101.

When a sharer evicts its clean copy, nothing is sent at all. The home is not told, so the bit stays at 1: a stale sharer bit. The next Invalidate to that node finds nothing to invalidate, useless but harmless. Only a Modified copy announces its eviction, with a Data Write-Back.

Modified: the home must ask the owner

Now Directory N0 Block B0 | Modified | 0100: N1 owns a dirty copy, and MM0 is stale. Give the block a value to see what moves: C1 holds x = 7, while MM0 still holds the old x = 3. N2 reads B0 (pp. 472–473).

The read miss needs four messages because the fresh value is in C1, not in MM0. The home sends a Fetch to the owner. N1 answers with a Data Write-Back and keeps a read-only copy, Modified → Shared. The home writes the block into MM0 and forwards it to N2 with a Data Value Reply. The state does not become Modified, because N2 only reads: Shared | 0110 (Fig. 2).

"The memory copy is now stale, but N1 and N2 have valid copies; N1 has the most up-to-date data."

Memory is up to date: the Data Write-Back of step 3 has just written the block into MM0, so MM0, C1 and C2 hold the same value.

Carrying the dirty block to the home, which writes it into memory, is what a Data Write-Back is for. The final state is Shared, and the notes' own invariant 2 (p. 478) reads "If state = S or U → memory is up-to-date". At the exam: after a read miss on a Modified block, both copies are Shared and the memory is up to date.

The write miss has the same four-message shape with one word changed: Fetch/Invalidate. N1 sends the block back and drops its copy, Modified → Invalid, and N2 becomes the new owner, Modified | 0010. For a moment MM0 is up to date again, refreshed by the Data Write-Back. But N2 asked for the block in order to write it, and once it writes, MM0 is stale once more.

"N1 (Remote) sends the data to Home (N0, Data Write-Back) and invalidates its copy, transitioning from Modified to Uncached state."

The cache block goes from Modified to Invalid. Uncached is a state of the directory entry, not of a cache block.

The papers keep the two lists apart. July 2024 asks for "the possible coherence states of a block in the local cache" (Invalid, Shared, Modified) and "in the home directory" (Uncached, Shared, Modified). June 2026 asks for "the final coherence state of the block in the home cache", and the answer is Invalid.

In the last case the owner starts the conversation: N1 evicts B0 to make room for another block. A dirty copy cannot be dropped, so N1 sends a Data Write-Back; the home writes it into MM0 and clears the entry: Uncached | 0000, memory up to date, one message (p. 475). The notes call N1 "Remote, Owner" here, because a Data Write-Back always travels remote → home.

Why does the data travel owner → home → local, and not straight to N2?

Because the home is the only place where the requests for B0 are put in order, and before anybody else sees the block it must update two things: the copy in MM0 and the entry. Going through the home costs a fourth message, but every request then finds a consistent entry. Real machines often let the owner send the block straight to the requester and a copy to the home, which saves a hop: the Stanford DASH machine of the resources did so. The June 2026 paper asks for "the reply message sent from the home node to the local node", and the notes' walkthroughs go through the home: so should your answer.

Every scenario of the protocol is now on the table. At the exam, read it by rows: find the state of the entry, then the request, and copy the shape with the actual node names.

The home's view: one state machine, six invariants

Follow only the entry through the walkthroughs. It goes Uncached → Shared when N1 reads, Shared → Shared when N2 reads too, Shared → Modified when N2 writes, Modified → Shared when another node reads, Modified → Modified when another node writes, Modified → Uncached when the owner evicts. Those six arcs, plus Uncached → Modified, are the whole directory state machine of p. 476 (the notes' Fig. 43): three states, three events — Read Miss, Write Miss and Data Write-Back — described "from the Home directory's perspective".

The table is the MSI protocol of lesson 35 seen from the home. With snooping, every cache watched the bus and took its own transition. Here the caches still have their Invalid, Shared and Modified states, but the decisions are taken in one place, and the bus events have become messages: a snooped read miss on a Modified block is now a Fetch, a snooped write miss is now an Invalidate or a Fetch/Invalidate, sent only to the nodes the bits name. One arc is missing on purpose: there is no Shared → Uncached, because a clean eviction is silent and the home never learns that the last sharer has left.

The notes' own summary of the arcs (p. 477) repeats the slip of p. 473 on the Modified → Shared arc:

"The memory copy remains stale, but both caches have valid copies (see page 472 for more details)."

After Modified → Shared the memory copy is fresh: the owner's Data Write-Back refreshed it before the reply went out.

State Shared with stale memory would break invariant 2 one page later. The bullet before it says the owner "sends the data to the requesting cache"; in the walkthrough it cites (p. 472, steps 3 and 4) the owner sends it to the home, which writes it into memory and forwards it.

The notes close the chapter with six invariants, conditions that must hold "regardless of the sequence of operations" (p. 478). Each is kept true by particular messages:

  1. Single owner: at most one cache holds the block Modified. Kept by the Invalidates and the Fetch/Invalidate that go out before the home grants Modified.
  2. Memory freshness: Shared or Uncached → memory up to date; Modified → memory stale. Kept by the Data Write-Back that every exit from Modified requires.
  3. Sharer set: the sharer bits list every node that holds a copy. Kept by every miss, which sets the requester's bit. After silent evictions the list may name too many nodes, never too few.
  4. Owner membership: in Modified the owner is the one bit set.
  5. State-transition correctness: states change only through the defined messages. (The notes' list leaves out Write Miss; add it.)
  6. Atomicity of updates: the directory processes one request at a time for a given block. With no bus to order the requests, this is how write serialization comes back: two Write Misses that arrive together are served one after the other.

The directory state machine is MSI seen from the home: Uncached means no copies, Shared means clean copies and fresh memory, Modified means one dirty owner and stale memory. Every message of the protocol is there to keep one of the six invariants true.

  3. Now send a silent eviction from N1, then one from N3. Does the entry change? Does any invariant break?
    What you should see

    No arc is taken, and the entry stays Shared | 0101 although no cache holds the block any more: the home is never told about clean evictions, which is why the machine has no Shared → Uncached arc. Every invariant holds — the bits name too many nodes, never too few.

  4. Choose "bug: the owner skips the Data Write-Back", Reset, send Write Miss from N2, then Read Miss from N0. Then Reset again, choose "bug: two requests served at once" and send two Write Misses at once from N1. Which invariants turn red each time?
    What you should see

    Without the write-back, memory freshness (2) and defined messages (5) fail, and N0 reads the old x from MM0 — the two caches disagree. With two requests served at once, C1 and C2 both end Modified while the bits name only N2: single owner (1), sharer set (3), owner membership (4) and one request at a time (6) fail. Each message of the protocol is there to keep one invariant true.

The exam exercise in seven moves

The three papers ask the same exercise in three forms. July 2024 asks for the definitions and the message lists (Question 1) and adds a three-access quiz (quiz question 4); June 2025 asks for three accesses with home, local, remotes, messages and the final entry (Question 1); June 2026 asks for one access in eleven boxes (Exercise 3). The moves below solve any of them. Here they solve the hook.

  1. Home. The node named in the entry: Directory N0 Block B0, so the home is N0. It is fixed by the address and never changes during the exercise.

  2. Read the bits. 1001 is N0 N1 N2 N3, so C0 and C3 hold clean copies; the state Shared says that MM0 is up to date.

  3. Local. The node the request comes from: a Write Miss from N2, so the local node is N2. C2 holds no copy, so it really is a miss.

  4. Remotes. Every other node whose bit is 1, or the owner if the state is Modified: N0 and N3. The home's own cache counts too (unless the home is the requester), so N0 is the home and a remote at once.

  5. Shape. Shared and a Write Miss: the memory answers and the sharers are told to leave, 1 + 2 + 1 messages.

  6. Messages, each with sender and receiver. N2 → N0 Write Miss (N2, B0); N0 → N3 Invalidate (B0) and N0 → C0, inside N0, Invalidate (B0); N0 → N2 Data Value Reply, with the block read from MM0. From the remotes to the home: nothing, because their copies were clean.

  7. Final states. C0 Invalid, C3 Invalid, C2 Modified; Directory N0 Block B0 | Modified | 0010; final owner N2; MM0 stale as soon as N2 writes.

Back to the hook. The answer is no: N0 and N3 send nothing to the home. Their copies are Shared, which means clean, identical to MM0, so there is no newer value to save; they simply invalidate. Only an owner in Modified answers the home, with a Data Write-Back, because only an owner holds a value that memory lacks. If you answered yes, you mixed up the two kinds of remote: a sharer drops its copy, an owner returns it. A real machine would send an invalidation acknowledgement, but the course's seven messages have none.

Five checks before you hand in the exercise. The home's own cache is a remote whenever its bit is 1, unless the home is the requester itself. A write hit sends an Invalidate, not a Write Miss, and receives no data. In Shared no Fetch is ever sent. After a read on a Modified block both copies are Shared and memory is up to date. A cache block is Invalid, never "Uncached".

Ten short answers. The marks hide in the directions: Invalidate appears twice (local → home and home → remote), and the remote → home list has a single entry, Data Write-Back — the June 2025 quiz asked exactly that. Keep the two lists of states apart: Invalid belongs to caches, Uncached to the directory.

(15 July 2024, Question 4, SINGLE ANSWER) Let's consider a directory-based protocol for a distributed shared memory system with 4 Nodes (N0, N1, N2, N3) where: Directory N1 Block B1 | State: Shared | Sharer Bits: 1001. Which is the state of the block B1 in N1 after this sequence: Read Miss B1 from local cache N1; Read Miss B1 from local cache N2; Write Hit B1 from local cache N1;

  • Answer 1: Directory N1 Block B1 | State: Shared | Sharer Bits: 1111 That is the entry after the two read misses; the write hit by N1 then invalidates the other three copies.
  • Answer 2: Directory N1 Block B1 | State: Modified | Sharer Bits: 0100 1001 → 1101 (N1 reads, local and home at once) → 1111 (N2 reads) → the write hit by N1 invalidates N0, N2 and N3: Modified, owner N1.
  • Answer 3: Directory N1 Block B1 | State: Shared | Sharer Bits: 0110 A read never removes a sharer: N0 and N3 keep their copies until the write hit, and after it the state is Modified.
  • Answer 4: Directory N1 Block B1 | State: Modified | Sharer Bits: 0110 In Modified exactly one bit is set: the owner's.
Show model answer

Answer 2. Read Miss from N1: N1 is local and home, the block comes from MM1 and N1's bit is set: Shared | 1101. Read Miss from N2: Data Value Reply from MM1: Shared | 1111. Write Hit from N1: N1 holds a Shared copy, so it sends an Invalidate request to the home (itself), which invalidates N0, N2 and N3: Modified | 0100.

Two traps: in the first access local = home, which changes nothing in the rule — N1's bit is set like any reader's, 1001 → 1101; the last is a write hit, so the final state is Modified with one bit, whatever the bits were before.

(SINGLE ANSWER) Let's consider a directory-based protocol for a distributed shared memory system with 4 Nodes (N0, N1, N2, N3) where: Directory N3 Block B3 | State: Shared | Sharer Bits: 0110. Which is the state of the block B3 in N3 after this sequence: Write Miss B3 from local cache N0; Read Miss B3 from local cache N2;

  • Answer 1: Directory N3 Block B3 | State: Modified | Sharer Bits: 1000 That is the entry after the write miss alone; the read miss from N2 then fetches the block from N0.
  • Answer 2: Directory N3 Block B3 | State: Shared | Sharer Bits: 1010 The write miss invalidates N1 and N2 (Modified | 1000); the read miss from N2 fetches from the owner N0, which keeps a Shared copy.
  • Answer 3: Directory N3 Block B3 | State: Shared | Sharer Bits: 1110 N1's copy was invalidated by the write miss and was never read again.
  • Answer 4: Directory N3 Block B3 | State: Modified | Sharer Bits: 0010 A read miss never makes the reader the owner: both copies end Shared.

Answer 2. Write Miss from N0: the home N3 invalidates N1 and N2 and replies to N0: Modified | 1000. Read Miss from N2: the home sends a Fetch to N0, which returns a Data Write-Back and goes to Shared; the home replies to N2: Shared | 1010, memory up to date.

The July 2024 quiz pattern with a read on a Modified block. The wrong options are the entry after one access (Answer 1), a forgotten invalidation (Answer 3) and a reader made owner (Answer 4).

(MULTIPLE ANSWERS) Let's consider a directory-based protocol for a distributed shared memory system with 4 Nodes (N0, N1, N2, N3) where: Directory N0 Block B0 | State: Modified | Sharer Bits: 0100. A Read Miss on B0 arrives from node N2. Which of the following statements are true?

  • Answer 1: The home node N0 sends a Fetch message to N1. N1 is the owner: the only node with the fresh value.
  • Answer 2: N1 sends a Data Write-Back to N0 and keeps its copy in Shared state. A Fetch downgrades the owner; a Fetch/Invalidate would invalidate it.
  • Answer 3: N1 sends the block directly to N2 with a Data Value Reply. In the protocol of the course the home replies: owner → home Data Write-Back, then home → local Data Value Reply.
  • Answer 4: At the end of the transaction, the copy of B0 in MM0 is up to date. The Data Write-Back wrote the block into MM0; the final state is Shared, so memory is fresh.
  • Answer 5: At the end of the transaction, the directory entry is Modified | 0010. N2 only reads: the entry becomes Shared | 0110.
Show model answer

Answers 1, 2 and 4. The sequence is N2 → N0 Read Miss, N0 → N1 Fetch, N1 → N0 Data Write-Back (N1: Modified → Shared, MM0 updated), N0 → N2 Data Value Reply. Final entry: Shared | 0110, memory up to date.

A multiple-answer quiz in the June 2026 form. Answer 4 is the statement the notes get wrong (pp. 473 and 477); Answer 3 describes a real-machine optimization, not the protocol of the papers.

Check yourself

Directory N0 Block B0 | Shared | 0110. N3 sends a Read Miss. Where does the Data Value Reply take the block from?

  • From MM0, the home's memory In Shared, memory is up to date (invariant 2): the home answers by itself, in two messages.
  • From C1, after a Fetch A Fetch goes only to an owner in Modified; C1's copy is clean and equal to MM0.
  • From whichever of C1 and C2 is closer to N3 That is cache-to-cache forwarding, not part of the protocol of the course — and nothing needs forwarding when memory is fresh.
  • From C2, which then becomes Invalid A read never invalidates anybody: N1, N2 and N3 all end Shared, bits 0111.

Directory N0 Block B0 | Modified | 0100. N2's Read Miss has just been served. What does MM0 hold now?

  • The same value as C1 and C2 N1's Data Write-Back wrote the block into MM0 before the home replied: Shared, memory fresh.
  • An old value, refreshed only when N1 evicts its copy That is what the notes print (p. 473), but the Data Write-Back of step 3 has already refreshed it; a clean copy is evicted silently anyway.
  • An old value, refreshed when N2 writes A write by N2 makes memory stale, not fresh — and it would first need an Invalidate request.
  • Nothing: the block left MM0 when N1 took it Memory always keeps a copy of the block; the only question is whether it is up to date.

Directory N0 Block B0 | Shared | 1001. N3 evicts its clean copy, then N2 sends a Write Miss. What does the home send?

  • An Invalidate to its own cache C0 and one to N3, then a Data Value Reply to N2 N3's eviction was silent, so its bit is still 1; the Invalidate to N3 finds nothing — useless but harmless.
  • An Invalidate to C0 only, then a Data Value Reply The home cannot know that N3 left: a clean eviction sends no message.
  • A Fetch to N3, then a Data Value Reply A Fetch is for an owner in Modified; the state is Shared.
  • Only a Data Value Reply, because nobody else holds the block C0 still holds a copy, and the bits say that N3 does too.

The home is N0. Which of these transactions use exactly four messages between nodes?

  • Read Miss from N2 when the entry is Modified | 0100 Read Miss, Fetch, Data Write-Back, Data Value Reply.
  • Write Miss from N3 when the entry is Shared | 0110 Write Miss, Invalidate to N1, Invalidate to N2, Data Value Reply: 2 + k with k = 2.
  • Write Miss from N2 when the entry is Uncached | 0000 Two: nobody to invalidate, so Write Miss and Data Value Reply.
  • Write Hit from N1 when the entry is Shared | 0110 Two: the Invalidate request and one Invalidate to N2; no data moves.
  • N1 evicts B0 when the entry is Modified | 0100 One: the Data Write-Back.

Counting rule: 2 when memory answers, 2 + k for a write miss with k sharers, 1 + k for a write hit, 4 when an owner must be asked, 1 for an owner's eviction.

Why does the directory's state machine have an arc Modified → Uncached but none Shared → Uncached?

  • A clean copy is evicted silently, so the home never learns that the last sharer has left Only a dirty copy announces its eviction, with a Data Write-Back; that message is the M → U arc.
  • Because a Shared block can never become uncached It can: every sharer may drop its copy. The home is just not told.
  • Because S → U would need a Data Write-Back, which only owners send No data needs to move for a clean copy; the point is that no message at all is sent.
  • Because memory is stale in Shared In Shared memory is up to date (invariant 2).

Directory N0 Block B0 | Shared | 1000. Write Misses from N1 and N3 reach the home in the same cycle. What does invariant 6 make the home do?

  • Serve one, say N1 (Modified | 0100), then the other, with a Fetch/Invalidate to N1 (Modified | 0001) One request at a time: the second finds a Modified entry and is served like any write miss on an owned block.
  • Reply to both from MM0 and set the bits to 0101 Two Modified copies would break invariants 1 and 4; the bug "two requests served at once" in the second widget shows it.
  • Drop the second request The second request waits; it is not lost.
  • Merge the two writes into one The two processors write different values: the home orders them, it cannot merge them.

Key take-aways

  • Every transaction goes through the home, and its shape is set by the state of the entry and the request: in Uncached and Shared the home answers from its own memory in two messages, plus one Invalidate per other sharer on a write; in Modified it needs four, because the owner must return the block first.
  • A clean sharer told to invalidate sends nothing back; the only remote → home message is the owner's Data Write-Back, in reply to a Fetch or a Fetch/Invalidate, or when the owner evicts.
  • After a Fetch both copies are Shared and memory is up to date again; after a Fetch/Invalidate memory is fresh only until the new owner writes; after the owner's eviction the entry is Uncached | 0000 and memory is fresh.
  • A write hit on a Shared block sends an Invalidate request to the home, which invalidates the other sharers; no data moves, and the entry becomes Modified with only the writer's bit.
  • The directory state machine (U, S, M driven by Read Miss, Write Miss and Data Write-Back) is MSI seen from the home; its six invariants — single owner, memory freshness, sharer set, owner membership, defined messages only, one request at a time — are what the messages buy.
  • In the exam exercise the home is the node of the entry, the local node is the requester, and the remotes are every other node whose bit is 1, the home's own cache included; cache states are Invalid, Shared, Modified, directory states Uncached, Shared, Modified.
