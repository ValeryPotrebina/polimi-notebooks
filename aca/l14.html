Tomasulo under pressure: structural squeezes and CDB fights

After this lesson you will fill the Tomasulo table of a paper in which almost no cycle is lost to a true dependence, name the structural cause of every lost cycle, and say which piece of hardware would have bought it back.

In February 2025 the written exam handed out eight instructions and a Tomasulo machine with two load/store stations, two FP units and a single integer station. The ADDI near the end has both of its operands in the register file from the first cycle on, and the integer ALU is idle — yet it is issued only at cycle 11. Add a third load/store station to cure that wait, and the CPI does not move by a hundredth: still 22 cycles, still 2.75.

Three months later the midterm asked for a software-pipelined loop: ten instructions, every memory access a cache hit, not a single true dependence until the last two instructions. Tomasulo, the champion of out-of-order execution, needs 22 cycles for it: CPI 2.2.

Where do the cycles go? And if you could add one piece of hardware to each machine — a station, a unit or a bus — which one would you choose? Keep the question. The stepper in the middle of the lesson lets you try every candidate, and the last section gives the answer.

Two papers, one machine family

Both exercises use the machine family of every official paper: a few reservation stations per class (two, sometimes one), named functional units with a latency, a single Common Data Bus, all cache hits. The stage rules and the table conventions are the ones of lesson 12; here they are only applied. Two things change from paper to paper and decide everything: how many stations and units each class gets, and which class the instructions crowd into.

The February 2025 paper (notes, page 542) numbers its instructions I0 to I7; the notes print the registers of the older papers with a dollar sign ($F0, $R0), the June 2026 paper drops it, and so does this lesson.

I0: LD   F0, A(R0)
I1: LD   F2, B(R0)
I2: FADD F4, F0, F2
I3: FADD F6, F4, F4
I4: SD   F4, C(R0)
I5: SD   F6, D(R0)
I6: ADDI R0, R0, 4
I7: BNE  R0, R1, LOOP

Machine of the February paper: 2 reservation stations (RS1, RS2) with 2 load/store units (LDU1, LDU2), latency 6; 2 reservation stations (RS3, RS4) with 2 FP units (FPU1, FPU2), latency 2; one reservation station (RS5) with 1 INT_ALU/BR unit (ALU1), latency 1. The memory latency is long, the FP latency short, and the integer class has a single station.

The midterm of 5 May 2025 (notes, page 514) numbers its loop body I1 to I10, as printed. It is the software-pipelined body that lesson 21 schedules on a VLIW; here it runs on Tomasulo, a different machine with different latencies, so do not compare the two CPIs.

I1:  SD    F4, 0(R1)
I2:  SD    F6, 0(R2)
I3:  FADD  F4, F0, F0
I4:  FADD  F6, F2, F2
I5:  LD    F0, 16(R1)
I6:  LD    F2, 16(R2)
I7:  ADDUI R1, R1, 8
I8:  ADDUI R2, R2, 8
I9:  ADD   R3, R2, R1
I10: BNE   R3, R4, SP_LOOP

Machine of the midterm: 2 reservation stations (RS1, RS2) with 2 load/store units (LDU1, LDU2), latency 4; 2 reservation stations (RS3, RS4) with one FP unit (FPU1), latency 4; 2 reservation stations (RS5, RS6) with 2 INT_ALU/BR units (ALU1, ALU2), latency 2. Four memory instructions for two stations, two FP additions for one unit, and one bus for ten results.

The dependence tables, recomputed

Part 1 of the February exercise asks for every true, anti and output dependence of the fragment, "with I# for Fx". Read each instruction from its sources: a true dependence (RAW) is a source written by an earlier instruction; an anti-dependence (WAR) is a destination that an earlier instruction still reads; an output dependence (WAW) is a destination written twice. A store has no destination at all, so I4 and I5 can only be readers in such a table; and I3 reads F4 twice but owes it to I2 once.

Every destination (F0, F2, F4, F6, R0) is written exactly once, so there is no output dependence; the four anti-dependences sit on an integer register although the template says "$Fy" — write R0 anyway. The dependences that cross to the next iteration (the next I0 reads the R0 that I6 wrote) are not asked.

The midterm's body (notes, page 513) is the opposite picture. Software pipelining has moved the data chain out of the iteration: the stores read the F4 and F6 of the previous pass, the additions read the F0 and F2 loaded in the previous pass. What is left inside the body is name reuse, plus the control tail.

So the FP half of the midterm never waits for a value. Keep that in mind: every cycle it loses from here on is structural — a station, a unit or the bus was taken — and the exam's Hazards column must say so.

Issue in order, one per cycle, into a free station of the class (a station is busy from ISSUE through WRITE RESULT inclusive). START EXEC = ISSUE + 1, or the producer's WRITE RESULT + 1, or the cycle after the unit's previous instruction wrote its result, whichever is last. WRITE RESULT = START EXEC + latency, one result per cycle on the single CDB, oldest instruction first. A store's WRITE RESULT is its memory write. CPI = last WRITE RESULT / number of instructions. Calibrate every table on the row the paper gives you: a load with latency 4 is 1 / 2 / 6.

February: a closed door at cycle 5

Walk the February paper with the rules, a few cycles per step; the table after the steps is what they build.

  1. Cycles 1–2. I0 issues into RS1 with its base register copied (Vk = R0) and starts on LDU1 at 2: six cycles, Write Result at 8. I1 issues into RS2 at 2.

  2. Cycles 3–4. I1 starts on LDU2 (write at 9). I2 issues into RS3 with neither operand ready: its fields hold the tags Qj = RS1 and Qk = RS2, the names of the stations that will produce F0 and F2 — parked, not stalled. I3 issues into RS4 with Qj = Qk = RS3. Both FP stations are now full, both FP units idle: nobody has operands.

  3. Cycle 5 is the cycle of the lesson. I4 is a store and needs a load/store station; RS1 holds I0 through its Write Result at 8, RS2 holds I1 through 9. No station, no issue: structural hazard, written STRUCTURAL in the Hazards column. And because issue is in order, the door is shut for everybody: I5 cannot issue, I6 cannot issue although R0 and the constant 4 are ready and ALU1 is idle, I7 cannot issue.

  4. Cycles 6–8. Only countdowns, until I0 broadcasts F0 with the tag RS1 at 8: RS3 captures it, and RS1 is free from the next cycle.

  5. Cycles 9–11. I1 broadcasts F2 at 9; RS3 has both operands; I4 at last issues into RS1, with Qj = RS3 for its store data and Vk = R0. At 10 I2 starts on FPU1 (write at 12) and I5 issues into RS2 with Qj = RS4. At 11 I6 issues into RS5 with both operands — six cycles late for a reason that has nothing to do with its own data.

  6. Cycles 12–13. I2 writes F4: RS4 and RS1 capture it; I6 starts on ALU1. I7 wants the only integer station, RS5, busy with I6 through its write at 13: STRUCTURAL again. At 13 I3 starts on FPU2 (FPU1 would do as well: only the latency matters), I4 starts its six-cycle store on LDU1, and I6 writes the new R0 while I4 and I5, which read the old R0, have not finished — harmless, because each station holds its own copy.

  7. Cycles 14–22. I7 issues at 14 with the new R0 and starts at 15. I3 writes F6 at 15 and RS2 captures it; I5 starts at 16, the cycle in which I7 resolves. Then only countdowns: I4 writes at 19, I5 at 22.

The eight Write Result cycles — 8, 9, 12, 13, 15, 16, 19, 22 — are all different, so the single bus never has to choose. That is why this paper is the clean one: its 22 cycles are made of the long memory latency and one structural hole.

What the hole did not change

Here is the first half of the puzzle. Give the February machine a third load/store station. I4 now issues at 5 (into RS3, with the FP stations renumbered RS4 and RS5), I5 at 9, I6 at 10 and I7 at 14; I6 even loses the bus at cycle 12 to the older I2 and writes at 13. The last Write Result is still 22, the CPI still 2.75. Look at the arrows of Fig. 2: I1 broadcasts at 9, I2 computes 10–11 and broadcasts at 12, I3 computes 13–14 and broadcasts at 15, I5 stores 16–21 and writes at 22. That chain is made of latencies and broadcasts only; no station count shortens it. What shortens it is a shorter latency: with FP latency 4 instead of 2 the same chain ends at 26 (CPI 3.25); with memory latency 4 instead of 6 it ends at 18 (CPI 2.25).

A missing station delays when instructions enter; a dependence chain of latencies decides when the last one leaves — and the table's last cycle belongs to the chain.

"RAW I2, F6" (the Hazard cell of FADD $F6, $F4, $F4, repeated on every later table up to page 559)

RAW with I2 for F4. F6 is the destination of I3 itself; the value it waits for is the F4 that I2 produces.

I3 reads F4 twice and writes F6; nobody writes F6 before it. The timing on the same pages is right (I3 starts at 13, the cycle after I2's broadcast at 12): only the label slipped, and it contradicts the timing it is supposed to explain.

RS3: Qj = "LDU1", Qk = "LDU2" (the station snapshot of cycle 3; page 546 likewise writes "FPU1" twice as the tags of RS4)

The tags are the names of the reservation stations that will produce the operands: Qj = RS1, Qk = RS2 for I2, and Qj = Qk = RS3 for I3.

The CDB broadcasts the pair <tag, value> and the tag is the producing station (the notes' own theory, page 157: "CDB ← ⟨tag = RS3, value = result⟩"); the notes themselves switch to RS names from page 549 on. At cycle 4 I2 has not even been assigned a unit, so "FPU1" is not defined yet. Fig. 4, in the next section, shows the mechanism.

"This means Tomasulo stops execution because it guarantees in-order issuance"

Only the issue stage stops. Execution continues: LDU1 and LDU2 keep counting down on the same page (3 and 4 cycles remaining) and write at 8 and 9.

The structural hazard is on the stations, which are checked at issue; the units and the bus are not involved. "Execution stops" would describe a scoreboard-like freeze, and would not explain why I0 and I1 still finish at 8 and 9.

RS2: Vj = "$F4" (the operand that arrives at cycle 15; the same cell on pages 556–559)

Vj = F6. RS2 holds I5, SD $F6, D($R0), whose store data is F6, broadcast by I3 at cycle 15.

The tag that RS2 took at issue (cycle 10) was RS4, the station of I3, whose destination is F6; F4 was broadcast at 12 by RS3 and captured by RS1 and RS4, not by RS2. Check it on the timing table of the same page: I5 starts at 16, the cycle after F6 arrives.

The midterm: when the bus is the bottleneck

Now the midterm, where the FP side owes nothing to anybody. Step through it; the table and the timeline below are the result.

  1. Cycles 1–4. I1 issues into RS1 with its copy of F4 and starts the store at 2 (latency 4: write at 6), so RS1 is busy through 6. I2 issues at 2, starts at 3, writes at 7. I3 issues at 3 with F0 ready in both operand fields and starts on FPU1 at 4 (write at 8). I4 issues at 4 with F2 ready.

  2. Cycle 5. I4 has its operands, but the only FP unit belongs to I3 through its Write Result at 8 — a structural wait at Start Exec, not at issue: Start Exec 9, Write Result 13. The single unit costs it four cycles (Start Exec 9 instead of 5). And I5, a load, finds RS1 busy until 6 and RS2 until 7: the door is shut again, this time for two cycles.

  3. Cycles 6–11. I1 writes at 6, I2 at 7, I3 broadcasts F4 at 8 — nobody waits for it: I1 copied the old F4 at cycle 1, which is the anti-dependence being free. I5 issues at 7, the cycle after RS1's release, and starts at 8; I6 issues at 8, starts at 9; I7 issues at 9, starts on ALU1 at 10; I8 issues at 10, starts on ALU2 at 11 — each two cycles later than its ideal slot. At 11 I9 wants an integer station: RS5 and RS6 are both busy, so it waits, and I10 waits behind it.

  4. Cycle 12 starts the fight. Two results are ready: I5 (started 8, latency 4) and I7 (started 10, latency 2). One bus, one result per cycle, oldest first: I5 writes F0, I7 waits and keeps RS5.

  5. Cycles 13–16. At 13 four results are ready — I4 (9 + 4), I6 (9 + 4), I7, I8 (11 + 2). The oldest, I4, writes F6; then I6 writes F2 at 14, I7 writes R1 at 15 and I8 writes R2 at 16, in program order. I7's write slipped from 12 to 15, so RS5 is free only from 16.

  6. Cycle 16. I9 issues into RS5, blocked since 11: three of its five lost cycles are the bus queue, two the two-cycle latency of the ADDUIs. R1 is in the register file and R2 is broadcast in this very cycle, so the station holds both values by the end of it.

  7. Cycles 17–22. I9 starts on ALU1 at 17 and writes R3 at 19. I10 issues at 17 into RS6 with Qj = RS5 (the station of I9) and Vk = R4, captures R3 from the bus at 19, starts on ALU2 at 20 and writes at 22. Ten instructions, 22 cycles, CPI 2.2 — and the only true wait in the whole table is the two cycles I10 spends on R3; everything else was a station, a unit or the bus.

If your convention lets a unit restart in the very cycle its result is written, I4 becomes 4 / 8 / 12 and the bus order shifts, but the end stays 22. Write the convention you use on your sheet.

Count where the 22 cycles come from and you find three structural causes — two load/store stations too few at 5–6, one FP unit at 5–8, one bus at 12–16 — and a single true wait, the two cycles I10 spends on R3. The causes form one chain from the first cycle to the last: I1's write at 6 frees RS1 for I5 (issue 7, write 12); the bus queue pushes I7's write to 15, which frees RS5 for I9 (issue 16, write 19); I10 starts at 20 and writes at 22.

Tags, not registers

Cycle 17 shows the one idea of Tomasulo that the exam checks in the station snapshots. I10 issues although R3 does not exist yet: a station needs no values to be allocated, only a free slot. In the Qj field of RS6 it writes the tag of the producer — RS5, the station holding I9 — and from then on it listens to the bus. When I9 finishes on ALU1, the bus carries the pair <RS5, value>; RS6 compares the tag with its Qj, matches, copies the value into Vj and clears Qj. The register file does the same with its own tag field for R3. Nothing in this exchange names ALU1. A unit is not a producer: it serves one station after another (ALU1 runs I7, then I9; in the FP class RS3 and RS4 share the single FPU1), so "the result of ALU1" would not say which instruction's result it is. The tag is the station, because a station holds exactly one instruction from issue to Write Result.

One bus, one result per cycle, oldest first — and a result that waits for the bus keeps its station, so the bus can block the issue of instructions that never needed a bus at all.

"ADDUI operations cannot start because instructions 5 and 6 need to read the R1 and R2 registers (WAR hazard)."

At cycle 5 the two ADDUIs have not even issued. They wait because I5 has no load/store station and issue is in order; an anti-dependence never delays anything in Tomasulo.

Stations copy their operands at issue, so the readers of the old R1 keep their copy whenever the new R1 is written. The page's own first sentences give the real reason ("no load/store reservation units available"), and the table on page 530 contradicts the WAR sentence: I7 starts at 10 while I5 is still executing.

"Therefore, we issue and start execution. At the end of execution, we will determine whether to write the result or wait."

There is nothing to determine at the end: an anti-dependence cannot postpone a Write Result. I3 writes F4 at 8 whatever I1, the reader of the old F4, is doing. Only the bus arbitration can delay a write.

The scoreboard of lesson 9 does check readers at Write Result; Tomasulo need not: I1 took its copy of F4 into RS1 at cycle 1 (Vj = F4 on page 514) and never reads the register again. Here I1 even finished at 6; the February paper shows the real case — the ADDI writes R0 at 13 while the stores that read the old R0 execute at 13 and 16, and nothing waits.

"The value will be sent on the Common Data Bus with the key ALU1. Instruction 10 writes the tag "ALU1" to the reservation station"

The key on the bus and the tag in Qj are the name of the reservation station of I9: RS5.

The notes' own theory page 152 writes "F6.Qi = RS1", and Fig. 4 shows why: a unit serves one station after another (ALU1 runs I7, then I9; FPU1 serves RS3 and RS4), so its name does not identify a producer; a station holds exactly one instruction until its Write Result. ALU1 gives the right numbers here, but it is not what the hardware compares.

"the reservation station reads the value from the common data bus and stores it in memory."

It stores the value in its operand field Vj and clears the tag Qj. Nothing goes to memory: I10 is a branch.

The snapshot on the same page shows exactly that: RS6 has R3 in Vj, the Qj field is empty, and the memory is not touched by any instruction after cycle 7.

The official contrast: when the bus bites twice

The official paper of 10 June 2025 uses the same exercise family with two units in every class, latencies 4, 3 and 2. Two things to say on the sheet. First, whether a branch takes a bus slot is not stated in the papers; this course lets it (it writes at 18), and an answer that writes 17 with the remark "the branch produces no register value" is defensible — the CPI is 22 / 8 = 2.75 either way, because the store I5 ends the table. Second, write the collision explicitly: "Structural (CDB at 12: I2 writes first)" is what turns a right number into a justified one.

The puzzle, answered

February: no station, no unit and no bus would change 22. Its last cycle is the chain F2 → F4 → F6 → memory, 6 + 2 + 2 + 6 cycles of latency plus the broadcasts between them; the shut door delayed four instructions by four cycles and cost not one cycle of the total. The only hardware that helps is faster hardware. The midterm: the bus. A second CDB takes the loop from 22 to 20 cycles, unlimited buses to 19, while a second FP unit buys one cycle and a third integer station none. Two ALUs sat idle for most of the 22 cycles; what they were waiting for was a slot on the bus and a free station behind it.

The bus has been the price of the idea from the start. Tomasulo's 1967 paper on the IBM System/360 Model 91 describes "a simple common data busing and register tagging scheme which permits simultaneous execution of independent instructions while preserving the essential precedences", for a machine that looked ahead about eight instructions. Only about fifteen Model 91s were built; the first went to NASA's Goddard Space Flight Center in October 1967. The scheme, and its single bus, outlived the machine.

Reading and writing the Hazards column

The column is where the examiner sees whether you know why a number is what it is. Write one label per cause, in the order the causes happened to the row. None: nothing delayed the row — issue at the cycle after the previous instruction, start the cycle after issue, write at start plus latency. Structural (which stations, which cycles): the row issued late because every station of its class was busy; name the stations and the cycles, as in "RS1, RS2 busy, cycles 5–8". A row behind such a row issued late too: say "issue delayed behind I4". Structural (unit): the row started late because the unit was busy — "FPU1 busy with I3 until 8". Structural (CDB at c: I# first): the row wrote late because an older result took the bus. RAW with I# (Fx): the row started the cycle after that producer's Write Result; if the operand was already there at issue, say so, as the June table does. WAR / WAW with I# (Fx): renamed: optional, and worth a line, because it shows you know they cost nothing.

"It could not start because of a WAR hazard" is never right in a Tomasulo table; "it could not issue because the unit was busy" is never right either. Issue checks stations; Start Exec checks operands and units; Write Result checks the bus. Put each cause at its stage and the cycle numbers follow.

Two of these causes are present in every exam machine, whatever the code: the single bus and the non-pipelined units. CDB and unit slider: who pays when results arrive together

The slider sets the number of Common Data Buses; the switch makes every unit pipelined, so that a new instruction may start on it every cycle instead of waiting for the previous one's Write Result. The readouts give the total cycles, the CPI and the number of tie-breaks on the bus; the note lists every tie-break with its loser.

  1. Units not pipelined, one bus. Predict: will any two results ever be ready in the same cycle? Then move the slider to two and three buses and watch the total.
    What you should see

    Never. 18 cycles, zero tie-breaks: I3 waits for FPU1 until I2 has written, I6 waits for ALU1 behind I5, so results arrive one at a time. More buses change nothing — 18, 18, 18. A bus only matters when results collide.

  2. Switch the units to pipelined with one bus. Predict the new total and the number of tie-breaks before reading the readouts.
    What you should see

    16 cycles — and three tie-breaks: at 10 I6 loses to I2, at 11 to I3, at 15 I7 loses to I4. Pipelining the units makes results arrive together, and the single bus becomes the thing they queue for.

  3. Keep pipelining and add buses: predict what the second bus buys and what the third one buys.
    What you should see

    The second bus removes all three collisions: 15 cycles, CPI 1.875. The third bus buys nothing: never more than two results are ready in one cycle here. Hardware pays off only up to the width of the worst collision.

Every exam table hides the same two taxes: a non-pipelined unit spreads results out, a single bus serialises the ones that still arrive together — and both are paid at Write Result, where the station is released.

Exam-style questions

Explain the main concepts and benefits of each one of the following techniques used by a Tomasulo-style processor: (1) reservation stations; (2) tags on the Common Data Bus; (3) in-order issue with out-of-order execution. For each, say what it costs, with an example from an exercise.

Show model answer

(1) A reservation station is a buffer in front of a class of functional units that holds an issued instruction together with its operand values (Vj, Vk) if they are already available, or the tags (Qj, Qk) of the stations that will produce them. Benefits: the instruction leaves the issue stage without waiting for its operands, so later independent instructions can issue; the station is also the renamed destination, which removes WAR and WAW stalls (the February 2025 ADDI overwrites R0 while two stores still hold their copies of the old R0). Cost: the number of stations bounds what can be issued; when every station of a class is busy, issue stalls (RS1 and RS2 busy at cycles 5–8 of the February paper).

(2) When a unit finishes, the result is broadcast on the Common Data Bus as the pair (tag, value), the tag being the station of the producer. Every station and register whose Qj, Qk or tag field matches captures the value in the same cycle, so a consumer can start the next cycle without a trip through the register file and without a stall on name dependences. Cost: one bus delivers one result per cycle; when two are ready the older goes first and the younger waits, keeping its station (midterm 2025, cycles 12–16: five results, I7 writes at 15 instead of 12).

(3) Instructions issue strictly in program order, one per cycle, but start executing as soon as their own operands and a unit are available, and finish out of order: long-latency instructions no longer block independent ones (I6 ADDI executes at 12 while the FP work is pending), the hardware tolerates unpredictable latencies such as cache misses, and the compiler needs no knowledge of the pipeline. Cost: in-order issue means one blocked instruction blocks everything behind it; out-of-order completion makes exceptions imprecise, and nothing can pass an unresolved branch until a reorder buffer (lesson 17) adds speculation.

Each sub-point is worth a short labelled block: concept, benefit, cost, example. A complete answer names the tag as the station, says that WAR/WAW cost nothing and why, and states the structural limits (stations, bus) next to the benefits.

In the Tomasulo algorithm a reservation station is released: (single answer)

  • when the instruction issues At issue the station is just filled.
  • when the instruction starts executing The station keeps the operands and the tag while the unit works.
  • when the instruction writes its result Correct: the station is busy through WRITE RESULT and can be reused from the next cycle.
  • when the next instruction of the same class issues The next instruction of the class needs a free station; it cannot free one.

Check yourself

February paper: at cycle 5 the ADDI has both operands in the register file and ALU1 is idle, yet it issues only at cycle 11. Why?

  • It has a RAW hazard on R0 with the loads The loads read R0; they do not write it. Nothing the ADDI needs is pending.
  • Issue is in order: the store I4 finds no load/store station until cycle 9, and I5 must issue before I6 Right. One missing station of another class costs the ADDI six cycles.
  • The Common Data Bus is busy with the loads The bus is used only at WRITE RESULT, at cycles 8 and 9.
  • Its anti-dependences on R0 must be resolved first Anti-dependences never delay anything in Tomasulo: the readers hold copies.

Which of these changes shorten the midterm's 22 cycles? (several answers)

  • A second Common Data Bus Yes: 20 cycles. I7 writes at 12 and RS5 is free for I9 at 13.
  • A second FP unit Yes, by one cycle: 21. I4 writes at 9, but the ADDUIs still queue behind the loads on the bus.
  • A third integer reservation station No: I9 issues at 11 but still waits for R2 until 16, and I10 waits for a station until 16; the last write stays at 22.
  • Four load/store units instead of two No: LDU1 and LDU2 were never both busy when a load was ready to start; the stations and the bus were the shortage, not the units.
  • Unlimited Common Data Buses Yes: 19 cycles; what remains is latency and the two true waits of the tail.

The picture to keep: the ALUs idle, the bus crowded, the stations held by results that cannot leave.

Midterm, cycle 13: I4, I6, I7 and I8 are all ready to write. Which one writes, and what happens to the others?

  • I7, because it has been ready the longest Time spent waiting does not count; program order does.
  • I4, the oldest; the others slip to 14, 15 and 16 in program order Right: oldest first, one per cycle, and each slipped write keeps its station a cycle longer.
  • All four: the bus can carry one result per unit A single CDB carries one result per cycle, whatever the number of units.
  • I8, because the integer unit has priority over the loads There is no priority by class in the course's convention; only age.

At cycle 17 of the midterm I10 issues into RS6 while R3 does not exist yet. What does RS6 hold in Qj?

  • ALU1, the unit that will compute R3 That is the notes' slip on page 530: a unit's name identifies no producer.
  • RS5, the reservation station holding I9 Right: the bus will carry the pair (RS5, value) and RS6 matches it against this tag.
  • The old value of R3 A stale value would make the branch wrong; the field holds a tag, not a value.
  • I9, the number of the instruction Instruction numbers are the exam's names; the hardware names producers by station.

A third load/store station is added to the February machine: I4 issues at 5 instead of 9, yet the last WRITE RESULT is still 22. Why?

  • Because the new station has no unit of its own I4 does start as soon as F4 arrives at 12 — on LDU1, which was free. The unit is not the reason.
  • Because the chain I1 → I2 → I3 → I5 (latencies 6, 2, 2, 6 plus the broadcasts between them) is untouched Right: stations change when instructions enter, latencies decide when the last one leaves.
  • Because I6 now loses the bus at 12 and that costs exactly the four cycles gained I6 does slip to 13, but I6 is not on the chain that ends at 22; it would be 22 without that slip too.
  • Because in-order issue cancels any gain from extra stations Extra stations do move issues forward (I4 from 9 to 5); they just do not shorten this chain.

The February ADDI writes the new R0 at cycle 13 while I4 and I5, which read the old R0, have not executed yet. Why is the result still correct?

  • Because the stores read R0 again from the register file when they start If they did, they would read the new R0 and store to the wrong address.
  • Because each store copied R0 into its own station at issue (Vk = R0) and never reads the register again Right: operand copying at issue is how Tomasulo makes anti-dependences free.
  • Because the ADDI is held in its station until the stores have started The table shows the opposite: the ADDI writes at 13, I5 starts at 16.
  • Because the hardware re-executes the stores if the address changed Nothing is re-executed; the old value was saved before the new one existed.

Key take-aways

  • Issue is in order and needs a free station of the class: one missing station is a stall for every instruction behind it, whatever its class and however ready its operands (February, cycles 5–8; the midterm, cycles 5–6 and 11–15).
  • A station is busy from ISSUE through WRITE RESULT; a result that waits for the bus keeps its station, so the bus can delay issues.
  • One CDB, one result per cycle, oldest instruction first; the midterm's queue 12–16 is the whole reason I9 issues at 16 and the loop takes 22 cycles.
  • A non-pipelined unit is busy through the Write Result of its instruction; the second FADD of the midterm waits four cycles for FPU1 (Start Exec 9 instead of 5).
  • Tags are station names: Qj = RS5 for the midterm's branch, Qj = RS1 and Qk = RS2 for the February FADD — never a unit, never a register.
  • Anti- and output dependences cost nothing: readers keep copies, the register's tag is overwritten; the February ADDI overwrites R0 at 13 with two readers still pending.
  • The last cycle of a table belongs to a chain of latencies, not to the stations: February stays at 22 with a third station and moves to 26 or 18 when a latency changes; the midterm answers to the bus (20 with two, 19 unlimited) more than to a second FP unit (21).
Issue
in order, one per cycle, needs a free RS of the class; RS busy from ISSUE through WRITE RESULT inclusive, reusable the next cycle
Start Exec
the latest of ISSUE + 1, the producer's WRITE RESULT + 1, and the cycle after the unit's previous WRITE RESULT (a unit is busy through the WRITE RESULT of its instruction)
Write Result
\(\text{START EXEC} + \text{latency}\), +1 per older result taking the single CDB in that cycle (oldest first); a store's write is its memory write
Tag
Qj / Qk = the RS of the producer; the CDB carries \(\langle \text{tag}, \text{value} \rangle\); readers copy values at issue, so WAR and WAW never stall
CPI
\(\dfrac{\text{last WRITE RESULT}}{\text{IC}}\): 22/8 = 2.75 (Feb 2025), 22/10 = 2.2 (midterm 2025), 22/8 = 2.75 (June 2025)
