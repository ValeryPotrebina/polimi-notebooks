"Figure 2: Specific implementation of the RISC-V Data Path." — and on p. 18, "Figure 4: Structure of RISC-V pipeline."

Both figures show Patterson and Hennessy's MIPS datapath, not a RISC-V one. The five stages and the four pipeline registers are the same, so the pictures still teach the right structure — but do not quote their bit positions as RISC-V.

"In an ideal scenario, a 5-stage pipeline should provide a speedup of 5× reducing execution time to: (5 + 4) × 2 ns = 18 ns"

50 ns to 18 ns is a speedup of 2.78×. The 5× is the ratio of the throughputs once the line is full (one instruction per 2 ns against one per 10 ns), which is the limit of \(nk / (k + n - 1)\) for \(n \to \infty\); the execution time of a finite program never shrinks by 5×.

Compute it: \(50 / 18 = 2.78\). The notes' explanation of the 9 cycles ("5 steps of the first instruction, 5 of the last, minus 1") works only because here \(n = k\): with six instructions it would still give 9, but the pipeline needs 10. The clean statement is \(k + n - 1\): the first instruction takes \(k\) cycles, each of the other \(n - 1\) adds one. A quiz that asks for the time of 100 instructions wants 208 ns and 4.81×, not 200 ns and 5×.

Discussed in: lesson 1 · The assembly line in silicon, section "Overlap, not speed: the assembly line"

"Since there is no memory operation, the instruction bypasses the ME stage." — and, in the stage tables: "ME: No memory access (skipped)", "WB: No write-back stage (skipped)"

No instruction skips a stage in the five-stage pipeline. An ALU instruction spends its fourth cycle in MEM doing nothing, a store spends its fifth cycle in WB doing nothing; every instruction has a latency of exactly five cycles.

Fixed latency keeps the pipeline in order with one instruction per stage: if ALU instructions moved from EX straight to WB, an ALU instruction behind a load would collide with it on the single register write port, and later results could be written before earlier ones (a WAW hazard). Pipelines with variable latency — the multi-cycle FP units of lesson 7 — create exactly these two problems and need extra hardware for them. The same wording returns on p. 17 ("stores do not have WB, ALU instructions skip ME"): read "idle" wherever the notes say "skipped".

Discussed in: lesson 1 · The assembly line in silicon, section "What each instruction does at each stop"

"WB: Update PC if branch is taken" (in the stage table of the conditional branch, under "ME: No memory access (skipped)")

Wrong stage. In the basic five-stage pipeline the comparison and the target address are computed in EX and the PC is loaded in MEM; nothing branch-related happens in WB, and a branch writes no register.

The notes themselves say so where branches are treated properly (p. 31: "ME Stage: Based on the comparison, update the PC to either PC + 4 (if not taken) or PC + offset (if taken)"), and so does Hennessy and Patterson's basic pipeline. Optimised pipelines move the decision into ID — the exam's VLIW exercises say "branch solved in ID stage" — earlier still, never later. The stage that updates the PC sets the branch penalty of lesson 4: with the PC loaded at the end of MEM the correct fetch starts in the branch's fifth cycle and three fetches are lost; put it in WB and the penalty comes out as four, one cycle too large.

Discussed in: lesson 3 · What “faster” means: the Iron Law, Amdahl and pipeline arithmetic, section "Pipeline arithmetic: cycles = IC + 4 + stalls"

"Thus, actual CPI is always greater than 1, even in well-optimized designs."

True for a single-issue pipeline only: it can complete at most one instruction per cycle. A processor that issues \(w\) instructions per cycle (superscalar, VLIW: lesson 8) has an ideal CPI of \(1/w\) and a real CPI well below 1.

"It requires 2 consecutive mispredictions to change the predicted outcome, thus adding stability."

"The PTA is typically stored in PC-relative format (offset from current PC)."

the BTB stores the predicted next PC — an absolute instruction address — precisely so that the fetch unit can load it into the PC in the same cycle without an addition. The PC-relative offset lives in the instruction encoding; it is what the ID-stage adder uses to compute the BTA.

"Map to the same cache line. They alias in the cache, leading to potential false hits and data corruption."

In a physically tagged cache two addresses with the same index and different tags cause a conflict miss: the tag comparison fails and one block evicts the other — never a false hit, never corrupted data. "Register Aliasing: occurs when different architectural registers map to the same physical register in the hardware, leading to false dependencies."

Inverted. "But in that case, the cache knows it is the only copy (because the bus transaction didn't see any sharer response)."

An MSI cache cannot know it: on an MSI bus a cache that holds the block Shared stays silent, so "nobody else has it" and "others hold it Shared" look the same to the requester. MESI must add an answer — the shared line — before a cache can choose E.

Check it in the MSI table: a snooped Read Miss on a Shared line is "stays S", no action, and memory supplies the block. Only a Modified holder reacts, and then the requester ends in S anyway. So the information the notes say MSI ignores is information MSI never collects. The shared line, pulled by every snooper that holds the block, is exactly what E costs in hardware.

"The MESI Protocol appeared in the early 1980s, notably with the Intel 486 (1989) being one of the first commercial CPUs to implement MESI."

MESI is the Illinois protocol, published by Papamarcos and Patel in 1984 for bus-based multiprocessors. Intel's first MESI cache was the write-back data cache of the Pentium (1993); the on-chip cache of the original 486 was write-through.

A write-through cache sends every write on to memory, so it never holds a dirty line: there is no Modified state to protect, and an Exclusive state would buy nothing, because E exists to make the first write to a clean line silent — which matters only when writes stay in the cache.

"P1 loads block 0, writes it, and transitions from Exclusive to Modified."

P1 goes from Invalid straight to Modified. A write miss is a single Write Miss on the bus (a read-exclusive): it fetches block 0 and invalidates the copies of P2 and P3 in the same transaction. The line never passes through Exclusive.

E is entered only by a read miss that no other cache answers (Fig. 39, note 2). Even if you split P1's write into "load, then write", the load would find P2 and P3 holding block 0 and land in Shared, not Exclusive — and the write would then need an Invalidate: two transactions instead of one Write Miss. The notes' own state machine (Fig. 39, p. 460) draws the write miss as a single arc from I to M, with footnote 4: "Fetch data from memory via the bus (read-exclusive) and invalidate other caches".
