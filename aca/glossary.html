1-bit predictor 1-bit BHT; flip-flopping

A BHT entry that remembers the last outcome: one surprise flips the prediction, so a loop branch is mispredicted twice per execution of the loop — at the exit and at the re-entry. The notes call it flip-flopping.

Lesson 5 See also: 2-bit predictor, BHT

2-bit predictor 2-bit BHT; ST, WT, WNT, SNT; saturating counter

Each BHT entry is a four-state machine: Strongly and Weakly Taken predict Taken, Weakly and Strongly Not Taken predict Not Taken, so a loop branch costs one misprediction per loop instead of two; only from a strong state are two surprises needed to change the prediction. The notes' figure jumps from a weak state to the strong state of the other side, where a pure saturating counter moves one step — on the papers' loops both predict alike.

Lessons 5 6 See also: 1-bit predictor, BHT

2-D torus torus

A 2-D mesh plus wrap-around links joining the ends of every row and column: 2P links, twice the mesh's bisection and about half its diameter.

Lesson 33 See also: mesh

2:1 cache rule

A direct-mapped cache of size N has about the same miss rate as a 2-way set-associative cache of size N / 2: associativity can be traded for size.

Lesson 25 See also: associativity

3 C's the three C's: compulsory, capacity, conflict

The classification of misses by cause, each with its own cure: compulsory (prefetching, larger blocks), capacity (a larger cache), conflict (higher associativity, a victim cache).

Lessons 24 25 See also: compulsory miss, capacity miss, conflict miss

A

Back to the letters
address coalescing coalescing unit

The GPU merges the addresses of a warp's 32 threads into as few wide memory transactions as it can: consecutive addresses cost a couple, a walk down a column of a matrix costs 32.

Lesson 32 See also: memory banks, warp

address space shared address space; private address spaces

The set of memory addresses a processor can use in its instructions. Shared: one global space, where a store by one processor is seen by a load of another; private: each processor has its own, and data moves only as messages.

Lesson 34 See also: shared-memory model, message passing

aliasing the notes' conflict problem; interference

Two or more branches map to the same predictor entry and overwrite each other's state, because the table keeps no tags. It costs accuracy, never correctness; bigger tables and gshare's XOR index reduce it.

Lessons 5 6 See also: BHT, gshare, synonym

AMAT average memory access time

AMAT = hit time + miss rate × miss penalty: the expected cost of one access, hits and misses included. With two levels, AMAT = L1 hit time + L1 miss rate × (L2 hit time + L2 miss rate × L2 miss penalty), with L2's local miss rate.

Lessons 22 24 26 See also: hit time, miss rate, miss penalty, split cache

Amdahl's law make the common case fast

The overall speedup when an enhancement affects a fraction F of the original execution time and speeds that part up by S: Speedup = 1 / ((1 − F) + F / S), never above 1 / (1 − F). Hence the rule “make the common case fast”: F, not S, moves the ceiling.

Lessons 3 8 See also: speedup

anti-dependence WAR dependence

Ii reads a register (or memory location) that a later Ij writes; it may become a WAR hazard if Ij writes first. A name dependence.

Lessons 7 12 See also: WAR, name dependence

architectural register logical register

A register named by the instruction set (F0, F2 … R1 …), a number that must fit in the register field of the instruction. There are few of them, which is why hardware renames onto more storage than the ISA shows.

Lessons 7 11 See also: register alias table, register renaming

ASAP scheduling as soon as possible

A schedule that puts every operation in the first cycle its operands allow, ignoring how many units the machine has; its length is the critical path.

Lesson 20 See also: list scheduling, critical path

associativity higher associativity

The number of lines (ways) in which a given block may be placed: 1 for direct-mapped, n for n-way, all of them for fully associative. Raising it reduces conflict misses only, not compulsory or capacity ones, and lengthens the hit time.

Lessons 23 25 See also: 2:1 cache rule, conflict miss

asymptotic CPI CPIAS = CPI∞; per-iteration CPIiter

The CPI of a loop with m instructions and k stall cycles per iteration over many iterations, when the fill cycles are diluted: CPIAS = (m + k) / m = 1 + k / m. One iteration alone, fill included, gives CPIiter = (m + k + 4) / m.

Lesson 3 See also: fill, ideal CPI

Back to the letters
barrier barrier synchronisation

A synchronisation point that no thread or process passes until all of them have reached it. In shared memory it orders a store before the loads that need it, since nothing else tells a reader that the store has happened; in a bulk-synchronous program every phase ends at one, so the slowest processor sets the pace.

Lesson 34 See also: bulk-synchronous, shared-memory model

basic block

A straight-line sequence of instructions with one entry and one exit: if its first instruction runs, all of them run, in order, which makes reordering inside it safe. Typical blocks hold only 4 to 7 instructions.

Lessons 19 20 See also: local scheduling, global scheduling

BHT branch history table; branch prediction buffer (H&P); the notes' Branch Outcome Predictor

A table indexed by the low-order bits of the branch's address, without tags, whose entry is a small state machine (1-bit or 2-bit) holding the prediction. It answers “whether”; the BTB answers “where”.

Lessons 5 6 See also: 1-bit predictor, 2-bit predictor, aliasing, BTB

binary compatibility binary incompatibility

Whether code compiled for one machine still runs correctly on the next. A VLIW schedule encodes the number of slots, the units and their latencies, so even a small change may require recompiling — the major limitation of static scheduling.

Lessons 8 19 See also: VLIW, static scheduling

bisection bandwidth total network bandwidth

The minimum total bandwidth of the links cut when the network is split into two equal halves: the worst case, half the nodes talking to the other half. The total network bandwidth, the sum over all links, is the best case: an 8-node ring with 1 GB/s links has 8 GB/s total and 2 GB/s bisection.

Lesson 33 See also: interconnection network, ring

block cache block; line, cache line

The unit moved between the levels of the hierarchy. A line is the row of the cache that holds one block, with its valid bit, its dirty bit, its tag and, in a set-associative cache, the LRU bits.

Lessons 22 23 See also: valid bit, dirty bit, tag (cache), block size

block size larger block size

Larger blocks turn spatial locality into fewer compulsory misses, but in a cache of fixed size they mean fewer lines — more conflict and capacity misses — and a longer miss penalty: the miss rate against block size is U-shaped.

Lesson 25 See also: compulsory miss, spatial locality

branch delay slot delay slot; delayed branch; cancelling branch

With a delayed branch the instruction right after the branch always executes, taken or not, and the branch takes effect after it. The compiler fills the slot from before the branch (always a win), from the target or from the fall-through. A cancelling branch (MIPS “branch likely”) executes the slot only when the branch goes the predicted way and squashes it otherwise — a variant the course's machines do not use: their slot always executes.

Lessons 4 19 See also: branch solved in ID

branch divergence

The threads of a warp take different paths of an if: the warp runs both paths, one after the other, with part of its lanes masked off — it costs what masking costs.

Lesson 32 See also: vector mask register, warp

branch history register BHR; global history register (GHR); local history

A shift register of recent branch outcomes (Taken = 1). Global — one register for all branches, the GHR of a correlating predictor, holding the last m outcomes whichever branches they came from — or local, one per branch, kept in a table indexed by the PC.

Lesson 6 See also: correlating predictor, pattern history table

branch outcome BO; Taken (T), Not Taken (NT)

Whether a conditional branch continues at its label (taken) or at PC + 4 (not taken). To fetch past a branch the processor needs the outcome and, for a taken branch, the target address.

Lesson 4 See also: branch target address, control hazard

branch penalty misprediction penalty

The fetch cycles lost on a branch: (stage at whose end the PC is written) − 1, three cycles with the PC written in ME, one with the branch solved in ID. With prediction it is paid only on a misprediction: CPI = 1 + fb × penalty × pmis.

Lessons 4 5 See also: branch solved in ID, control hazard

branch solved in ID early evaluation of the branch

The comparison and the target adder moved into the ID stage, so the next PC is known one cycle after the fetch and the branch penalty drops from three cycles to one. The papers' VLIW machine says “The branch is completed with 1 cycle delay slot (branch solved in ID stage)”; since the comparator in ID needs its operands a stage early, the integer unit has a 2-cycle latency to a following branch.

Lessons 4 19 See also: branch penalty, branch delay slot

branch target address BTA

Where a taken branch continues: PC + the sign-extended offset of the instruction. A scheme that knows “taken” but not “where” still cannot fetch.

Lesson 4 See also: BTB

BTB branch target buffer; PTA, predicted target address

A small cache, indexed and tagged by the branch's address, whose data is the predicted target address of a taken branch, so the next fetch comes from the target with no bubble. The BHT predicts whether, the BTB where; the BTB needs tags, because a false hit would redirect fetch after an instruction that is not even a branch.

Lessons 4 5 See also: BHT, branch target address

BTFNT backward taken, forward not taken

A static rule: predict a backward branch as taken, because backward branches close loops, and a forward branch as not taken, because forward branches usually guard a path that is rarely entered. It is not adaptive.

Lesson 4 See also: static branch prediction

bulk-synchronous BSP

Data-parallel programs that alternate local computation with global communication or a barrier (Valiant's BSP model); every phase lasts as long as its slowest processor.

Lesson 34 See also: SPMD, barrier

bundle long instruction word

One VLIW instruction: one slot per functional unit, each holding an operation or a NOP, fetched by one PC and executed in parallel — one row of the exam's VLIW table. A bundle holds at most one branch.

Lesson 19 See also: VLIW, issue slot, NOP

bus shared bus

A single shared medium joining processors, memory and I/O: cheap, simple and a broadcast medium — what snooping needs — but it carries one transaction at a time and saturates at a few tens of processors.

Lessons 33 35 See also: interconnection network, snooping protocol

C

Back to the letters
cache

A small, fast memory close to the processor that keeps copies of data from main memory, to reduce the average time needed to access data and instructions.

Lesson 22 See also: block, four questions, AMAT

cache coherence problem

Private caches hold their own copies of a shared block, so after one processor updates its copy the others may still read an old value — which breaks the shared-memory programming model.

Lesson 35 See also: coherence

capacity miss

A miss because the cache cannot hold all the data the program is working on: the misses of a fully associative cache of the same size, minus the compulsory ones. A larger cache reduces them.

Lessons 24 25 See also: 3 C's

chaining

The vector form of forwarding: each element of a result goes straight from one unit into the next, so a dependent instruction starts before the whole vector is written and can share its producer's convoy. Without chaining it waits for the last element.

Lessons 30 31 See also: convoy, forwarding

chime

The time one convoy takes: VL clock cycles when every unit handles one element per cycle, start-up ignored. A sequence of convoys takes one chime per convoy — 4 convoys × 16 elements = 64 cycles.

Lesson 31 See also: convoy, lane, start-up latency

clock cycle time TCLK, clock period; clock frequency fCLK

The duration of one clock cycle, TCLK; the clock frequency is fCLK = 1 / TCLK, in hertz. In a pipeline TCLK must fit the slowest stage plus the pipeline-register overhead.

Lessons 1 3 See also: CPU time, pipeline imbalance and overhead

cluster

Independent computers, each with its own processors, private memory, disk and operating system, joined by a network: no shared address space, so nodes exchange explicit messages (MPI). It scales to tens of thousands of nodes on commodity hardware.

Lesson 34 See also: message passing

coarse-grained multithreading

Runs one thread until a long-latency stall, typically a miss to DRAM, then switches to another; the switch drains and refills the pipeline. Simple, but useless against short stalls such as data hazards and mispredictions.

Lesson 29 See also: fine-grained multithreading, vertical and horizontal waste

code efficiency

The fraction of the issue slots of a schedule that hold real operations: IC / (#cycles × #issues), with IC the operations of one iteration, #cycles its cycles (delay slot included) and #issues the slots per bundle. It measures the NOPs of a VLIW schedule.

Lessons 8 19 20 21 See also: NOP, FP ops per cycle

code scheduling instruction scheduling

Reordering instructions so that independent work fills the cycles in which a dependent one would wait, while every true dependence is still respected.

Lesson 15 See also: loop unrolling, list scheduling

coherence coherent memory system

A memory system is coherent when a processor reads back its own last write to a location if no other processor wrote it in between; a read sees another processor's write once enough time has passed (write propagation); and all processors see the writes to one location in the same order (write serialization).

Lesson 35 See also: write propagation, write serialization, memory consistency

commit retire; architectural state

The last stage of speculative Tomasulo: the instruction at the head of the ROB, once Ready — and, in the course's tables, no longer speculative — writes its value into the register file or memory and frees its entry. The only stage that changes the architectural state (registers and memory), always in program order.

Lessons 13 17 18 See also: reorder buffer, precise exception

common data bus CDB

The bus on which a finishing unit broadcasts the pair ⟨tag, value⟩ to every station, buffer and register waiting for that tag; the tag names the producer, not the destination. With a single CDB one result is written per cycle, the oldest first, and the other suffers a structural stall.

Lessons 11 12 13 See also: tag (Tomasulo), structural hazard

compensation code

Copies of moved instructions placed on the paths that leave or enter a trace, so that the off-trace path still executes what trace scheduling moved across a branch.

Lesson 21 See also: trace scheduling

compiler optimisations merging arrays, loop interchange, loop fusion, blocking (tiling)

Reordering data or loops so the program's accesses fit the cache: merging arrays (fields used together share a block), loop interchange (walk along consecutive addresses), loop fusion (use a value right after it is produced) and blocking (reuse a B × B tile while it is cached — it pays only when data are used again, as in matrix multiplication).

Lesson 25 See also: spatial locality, temporal locality

compulsory miss Cold-start Miss (the exam's term); cold miss

The first reference to a block, which cannot be in the cache yet: it misses even in an infinite cache. Larger blocks and prefetching reduce compulsory misses.

Lessons 23 24 See also: 3 C's

conflict miss collision miss; interference miss

A miss because too many blocks map to one set and evict each other while the cache is not full: your cache's misses minus those of a fully associative cache of the same size. More ways and a victim cache reduce them.

Lessons 24 25 See also: 3 C's, victim cache

context switch

The operating system saves one thread's registers, PC and status and restores another's, changing the memory mappings between processes: thousands of cycles — fine for multitasking, far too slow to hide a cache miss.

Lesson 29 See also: hardware context

control dependence

Ij is control dependent on a branch when whether Ij executes depends on the branch's outcome, unknown when Ij would enter the pipeline. Delay slots, predication and speculation move instructions across it without changing the program's data flow or its exceptions.

Lesson 7 See also: hardware-based speculation, predication, branch delay slot

control hazard branch hazard

The next instruction to fetch is unknown because a branch — or any instruction that writes the PC — has not been resolved. Fetch can stall until the PC is known, or guess and flush the instructions fetched on the wrong path.

Lessons 1 2 4 See also: branch penalty, branch delay slot, dynamic branch prediction, flush

convoy

A set of vector instructions that execute together, each on its own unit: at most one instruction per unit (the load/store unit included), and an instruction that needs a vector produced in the same convoy may join only with chaining. Time ≈ number of convoys × chime.

Lesson 31 See also: chime, chaining

correlating predictor (m, n) predictor: (1,1), (2,2); two-level predictor

A dynamic predictor that chooses the counter by the branch's address and by the outcomes of the last m branches: 2m tables of n-bit counters, selected by the global history and indexed by k PC bits, 2m × n × 2k bits in all. It learns that one branch's outcome depends on another's.

Lesson 6 See also: branch history register, two-level adaptive predictor, gshare

CPI clock cycles per instruction; weighted CPI

The average number of clock cycles per instruction: total clock cycles / IC. For an instruction mix, CPI = Σ CPIi × Fi, where Fi = Ii / IC is the fraction of the executed instructions that belong to class i.

Lesson 3 See also: IPC, ideal CPI, asymptotic CPI, CPU time

CPU time the Iron Law

The processor's time on a program: CPU time = IC × CPI × TCLK = IC × CPI / fCLK, each factor set by a different design level. With cache misses, CPI = CPIexec + memory accesses per instruction × miss rate × miss penalty.

Lessons 3 24 See also: CPI, IC, clock cycle time

critical path

The longest chain of dependent operations weighted by their latencies: no machine can finish the block sooner. The VLIW exercises report it as the cycles of one iteration, delay slot included; in hardware, the slowest path through a stage sets TCLK — often the L1 hit.

Lessons 7 20 28 See also: dependence graph, ASAP scheduling, hit time

crossbar crossbar switch

One switch with P² crosspoints that connects any input to any output, several pairs at once: non-blocking, one link per node, a bisection of P / 2 links. The notes' “Crossbar (Fully Connected Switch Network)” and its formulas describe the fully connected network instead.

Lesson 33 See also: fully connected network, topology

CUDA kernel; grid; thread block

NVIDIA's programming model: a kernel is written for one thread — one element — and launched as a grid of thread blocks. A block runs on one SM, its threads share an on-chip memory and can wait at a barrier; blocks are independent, so a kernel scales with the number of SMs.

Lesson 32 See also: warp, host and device

data dependence true dependence; true data dependence

Ij reads a value that an earlier Ii produces, directly or through a chain. It may become a RAW hazard, and it is the one dependence that renaming cannot remove.

Lessons 7 12 See also: RAW, name dependence

data hazard

An instruction needs a result that an earlier one has not produced yet — or, once instructions can overtake each other, would read or write a register in the wrong order. Its three kinds are RAW, WAR and WAW.

Lessons 1 2 See also: RAW, WAR, WAW, data dependence

data-level parallelism DLP

The same operation applied independently to many data items, so that no element waits for another's result — a property of the program that SIMD and vector hardware exploit.

Lesson 30 See also: SIMD, vector processor

Data Value Reply

Home → local: the block itself, the answer to every Read Miss and Write Miss.

Lessons 37 38 See also: Read Miss, Write Miss

Data Write-Back

Owner → home, the only message from a remote node: the dirty block, in reply to a Fetch or a Fetch/Invalidate, or when the owner evicts a Modified block; the home updates its memory.

Lessons 37 38 See also: Fetch, owner

DAXPY double-precision a × X plus Y

Y = a × X + Y in double precision, the benchmark loop of vector machines: 6 VMIPS instructions instead of 578 scalar ones; 3 convoys with chaining, 4 without.

Lessons 30 31 See also: VMIPS, convoy

dependence

A property of the program: one instruction needs, or reuses the name of, what another touches — a data, a name or a control dependence. It may become a hazard on a given pipeline, and a hazard may cost a stall; neither step is automatic.

Lesson 7 See also: hazard, stall, data dependence, name dependence, control dependence

dependence graph DAG, directed acyclic graph

One node per instruction and an edge from I to J whenever J must wait for I — RAW, WAR or WAW — labelled with the latency. Its longest weighted chain is the critical path.

Lesson 20 See also: critical path, list scheduling

diameter and degree diameter; degree; ports per node

Diameter: the largest number of links on the shortest path between two nodes, the worst-case distance; degree: the links per node, the ports of its router, a measure of cost. Ring: P / 2 and 2; hypercube: log2 P and log2 P.

Lesson 33 See also: topology

direct-mapped cache direct mapped

Every block has exactly one possible line: line = block address mod number of lines. The fastest hit, but two blocks that share a line evict each other.

Lessons 23 25 See also: set-associative cache, conflict miss

directory directory-based protocol; D0–D3

A hardware table in each node's memory controller with one entry per block of that node's memory: the block's coherence state and its sharer bits, never the data. Requests travel point-to-point to the block's home, so coherence scales beyond a bus.

Lessons 34 37 38 See also: directory state, sharer bits, home node

directory state Uncached, Shared, Modified; Modified (Exclusive) in some texts

Uncached: no cache has a copy, and memory holds the only valid one; Shared: one or more caches hold read-only copies, and memory is up to date; Modified: exactly one cache, the owner, holds a read-write copy, and memory is stale.

Lessons 37 38 See also: directory, sharer bits, Invalid (I)

dirty bit D; Dirty bit (exam column)

A bit per line of a write-back cache, set when the block is written in the cache: memory holds a stale copy, and the block must be written back when evicted. Dirty means memory is stale, not that the cache is wrong.

Lesson 23 See also: write-back

DRAM dynamic RAM

Dynamic RAM: one transistor and a capacitor per bit, whose charge leaks and must be refreshed — dense and cheap but slower; used for main memory.

Lesson 22 See also: SRAM

DSM distributed shared memory; cc-NUMA; nodes N0–N3

Physical memory distributed among the nodes, one shared address space: any processor can load any address, at a latency that depends on where the address lives. The notes use NUMA, DSM and cc-NUMA as synonyms; coherence is kept by directories.

Lessons 34 37 38 See also: directory, home node, NUMA

duplicate tag array duplicate snoop tags; snoop tag store

A second copy of the tags and coherence states, used only by the snooping controller, so bus transactions are checked without stealing cycles from the processor's own tag lookups.

Lesson 35 See also: snooping protocol

dynamic branch prediction

Hardware that observes how each branch behaved at run time and predicts its next outcome from that history — a BHT, a correlating or a two-level predictor. Nothing is decided by the compiler: the same binary adapts to its input.

Lessons 5 6 See also: BHT, correlating predictor, static branch prediction

dynamic loop unrolling

The notes' name for what Tomasulo does on a loop: several iterations in flight at once, their identical register names renamed by the station tags — as if the loop had been unrolled, though nobody copied the code.

Lesson 16 See also: loop unrolling, dynamic register renaming

dynamic register renaming implicit register renaming; hardware renaming

Renaming by the hardware at issue: in Tomasulo the station or buffer that will produce a result becomes its name (its tag), and a register accepts a broadcast only from its youngest writer. WAR and WAW hazards disappear; RAW dependences stay.

Lessons 11 13 15 16 See also: register renaming, tag (Tomasulo)

dynamic scheduling

The hardware rearranges at run time the order in which instructions execute, to reduce stalls, while preserving data flow (every consumer gets the value program order designates) and exception behaviour (the same exceptions are raised). Issue stays in order, execution goes out of order — the scoreboard and Tomasulo.

Lessons 7 8 9 See also: static scheduling, out-of-order execution, scoreboard, Tomasulo's algorithm

early restart and critical word first early restart; critical word first; wrapped fetch

With early restart the block arrives in normal order and the requested word goes to the processor as soon as it arrives; with critical word first (wrapped fetch) the memory sends the requested word first and wraps around the rest of the block. Both let the processor resume before the whole block is in.

Lesson 26 See also: miss penalty

exception interrupt; trap

An event that transfers control to a handler: a page fault, an illegal opcode, an overflow, a divide by zero. In the five-stage pipeline each stage only sets a flag that travels with the instruction; the flags are checked at WB, so exceptions are taken in program order.

Lesson 7 See also: precise exception, page fault

Exclusive (E) Excl (1) in a table cell, the number being the block held

The MESI state of a line that is valid, clean and present in no other cache: the processor may write it without a bus transaction (E → M silently), and it drops to S when another cache reads the block. Only a read miss that no other cache answers enters E: there is no arc from S to E, so the last Shared copy stays S after the others leave silently.

Lesson 36 See also: MESI, shared line

execution time response time; performance = 1 / execution time

The time to complete one task: lower is better, and performance is its reciprocal. “X is n% faster than Y” means ExecTime(Y) = (1 + n / 100) × ExecTime(X) — a ratio of times, never a difference.

Lesson 3 See also: CPU time, throughput

F

Back to the letters
false sharing

Two processors write different words that sit in the same block: no word is shared, yet coherence acts on the whole block — one Write Miss per burst under write-invalidate, a bus transaction per write under write-update.

Lesson 35 See also: write-invalidate, block

fat tree tree

A tree connects P nodes cheaply, with P − 1 small switches, but its bisection is one link, at the root; a fat tree thickens the links towards the root and recovers P / 2 — the standard fabric of HPC clusters.

Lesson 33 See also: cluster

Fetch

Home → owner when a Read Miss finds the block Modified: the owner sends the block back with a Data Write-Back and keeps a read-only copy, Modified → Shared.

Lessons 37 38 See also: Fetch/Invalidate, Data Write-Back

Fetch/Invalidate

Home → owner when a Write Miss finds the block Modified: the owner sends the block back and invalidates its copy, Modified → Invalid.

Lessons 37 38 See also: Fetch, Data Write-Back

fill pipeline fill; the “+4”

The cycles before the first instruction leaves the pipeline, one fewer than the number of stages: 4 in the five-stage pipeline, hence clock cycles = IC + stall cycles + 4 on the formula sheet. They are paid once per run and only diluted by a long program, never removed.

Lessons 1 3 See also: asymptotic CPI, speedup

fine-grained multithreading

Switches thread every cycle, usually round robin, skipping the stalled ones: short and long stalls are hidden while any thread is ready, but each thread issues only every few cycles.

Lesson 29 See also: coarse-grained multithreading, simultaneous multithreading

five-stage pipeline IF · ID · EX · MEM (ME) · WB; the RISC-V pipeline

IF fetches the instruction and computes PC + 4; ID decodes it and reads two registers; EX uses the ALU for the operation, the address or the branch comparison; MEM accesses the data memory (loads and stores only); WB writes the destination register. Five stages because five resources — instruction memory, register read ports, ALU, data memory, register write port — each used at most once by an instruction, always in the same stage.

Lesson 1 See also: pipeline register, pipelining

flush squash; fetch and flush

Throwing away the instructions that entered the pipeline on a wrong guess: they become NOPs and fetch restarts at the right address. In the five-stage pipeline a mispredicted branch flushes the instructions fetched on the wrong path; with a reorder buffer a mispredicted branch or a faulting instruction has every younger entry flushed, and since none of them has committed, the architectural state needs no repair.

Lessons 4 17 See also: control hazard, branch penalty, reorder buffer

Flynn's taxonomy SISD, SIMD, MISD, MIMD

Classifies machines by their numbers of instruction and data streams: SISD (a scalar pipeline, and also a superscalar), SIMD (vector units, GPU warps), MISD (essentially hypothetical) and MIMD (multiprocessors, multicores). It counts streams, not width.

Lessons 30 33 See also: SIMD, multiprocessor

forwarding bypassing; forwarding unit

A wire from a pipeline register straight to the input of a unit, plus a multiplexer, so a result reaches its consumer before it is written into the register file; the forwarding unit compares the registers and sets the multiplexers. With full forwarding a load followed at once by a user of its value still costs one stall (load-use), and a branch solved in ID still waits one cycle for an ALU result produced right before it, two after a load.

Lessons 2 10 See also: forwarding paths, load-use hazard, chaining

forwarding paths EX/EX path, MEM/EX path, MEM/MEM path

EX/EX, from the EX/MEM register to the ALU, serves an ALU result needed by the very next instruction, with no stall; MEM/EX, from MEM/WB to the ALU, serves an ALU result at distance 2, or a loaded value after the one load-use stall. MEM/MEM, from MEM/WB to the data memory, serves a load followed by a store of the loaded value.

Lesson 2 See also: forwarding, load-use hazard

four questions placement, identification, replacement, write strategy

Every cache design answers four questions: where can a block be placed, how is it found, which block is replaced on a miss, and what happens on a write. Virtual memory answers them too: anywhere (fully associative), through the page table, approximately LRU, write-back.
